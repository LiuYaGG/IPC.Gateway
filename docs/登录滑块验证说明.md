# 登录滑块验证

登录页采用本地滑块拼图，不依赖互联网、第三方验证码平台或本机图形组件。Windows、Linux 和 Docker 使用相同实现。

## 使用方式

1. 输入账号和密码，点击“点击完成安全验证”。
2. 在居中的弹窗中拖动滑块，将拼图移入缺口，松开后由服务器验证。
3. 通过后登录页显示绿色“验证通过”，再点击“登录”。

也可以用方向键微调位置，按住 Shift 每次移动 10 个源图像素；按 Enter 或点击“验证”提交。图片会随弹窗宽度缩放，界面支持中英文。

拼图位置错误会自动更换题目。取消、超时或验证失败不会跳过校验。

## 有效期与双机热备

- 拼图挑战和验证通过后的登录凭证分别有效两分钟。
- 每道题仅允许提交一次；一次错误也会使该题失效。
- 每张登录凭证只能用于一次登录尝试，密码错误后也需要重新验证。
- 挑战和凭证只保存在签发节点的内存中，不写项目、历史库或共享业务数据库。
- 服务重启或代理把后续请求转到另一节点后，原验证码会失效，重新完成验证即可。
- 使用反向代理时，请正确配置可信代理，以便服务器取得真实客户端 IP；否则多个用户会共用代理 IP 的限额。

## 服务端保护

登录接口必须先消费服务器签发的凭证，再校验账号密码。前端显示状态不能代替服务器校验。

拼图和凭证绑定经可信代理处理后的客户端 IP。默认按滑动一分钟限制：每 IP 最多生成 12 道题、提交 24 次验证、尝试 12 次登录；每节点对应上限为 300、600、300 次。超限返回 HTTP 429，并提示稍后重试。原有账号密码错误锁定机制继续生效。

挑战、凭证及客户端限流记录都有容量上限和过期清理；返回内容禁止缓存。服务器只发送背景 PNG、透明拼图块和显示尺寸，不在响应字段中发送正确水平位置。

本地拼图可配合限流减少自动化登录尝试，不保证抵御专门的图像识别攻击。

## 登录接口变化

网页已自动完成新接口调用：

| 接口 | 方法 | 用途 |
| --- | --- | --- |
| `/api/auth/captcha/challenge` | POST | 获取随机拼图及挑战编号 |
| `/api/auth/captcha/verify` | POST | 提交 `challengeId` 和源图像素坐标 `offsetX`，通过后取得 `verificationToken` |
| `/api/auth/login` | POST | 提交 `username`、`password`、`captchaToken`，其中 `captchaToken` 为上述验证凭证 |

直接调用旧登录接口且只提交账号密码的客户端，将收到“请先完成滑块验证”。外部业务接口可继续使用已配置的 API Token 认证。

更新时需要同时部署新前端与后端；无需额外安装服务或修改数据库结构。
