# OPC UA 标签路径与配置同步

## 标签路径

网关对外发布的变量节点，其字符串 NodeId、BrowseName 和 DisplayName 统一使用名称组成的完整路径：

- 设备直属标签：`西门子通道.西门子plc.bool1`
- 分组下标签：`西门子通道.西门子plc.压力测试_DB1.PT_DB1_Bool_001`

不再使用 `tag:通道ID/设备ID/分组ID/标签ID` 作为对外变量 NodeId。文件夹仍保留原有层次结构；读取、写入和实时值更新在网关内部继续按标签ID定位，不受显示名称变化影响。

客户端使用的完整 NodeId 为 `ns=<标签命名空间索引>;s=<完整路径>`。命名空间URI默认为 `urn:ipc-gateway:tags`，索引应以实际服务端浏览结果为准，不应假定固定为2。

名称本身包含点号或反斜杠时，路径分量中的反斜杠转义为 `\\`、点号转义为 `\.`，防止直属标签 `x.y` 与分组 `x` 下的标签 `y` 产生相同 NodeId。普通名称不受影响。

## 配置同步

通过设备管理保存标签及所属通道、设备、分组的配置时，网关增量同步 OPC UA Server 地址空间：

- 新增标签会增加相应节点。
- 标签、通道、设备、分组改名后，按新名称生成路径；旧路径失效。
- 删除标签或其所属对象后，相关变量从地址空间移除。
- 地址、数据类型、读写权限等配置会随地址空间重建生效。

普通标签配置应用不再重启整个 OPC UA Server，未变化的变量尽量保留原对象。更名改变了变量 NodeId，原 NodeId 的订阅需改为订阅新路径。部分客户端缓存浏览树，不会自动刷新节点列表，需要在客户端重新浏览；服务端已移除的旧节点不能再正常读取。完整项目重载等操作仍可能重启Server。

## 验证

此前完整路径功能的19项隔离测试覆盖过路径读取、写入和重建后的改名、删除。新增的增量同步按用户要求只完成编译和静态检查，运行验证交由用户进行，不能视为已经完成相同的增量行为实测。没有连接真实PLC或修改正在运行的Windows服务。
