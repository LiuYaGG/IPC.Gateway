# 驱动签名与强制验签

## 在界面签名

1. 使用管理员或同时具有安装升级查看权限和证书管理权限的账户登录。
2. 打开“安装升级”，在“协议驱动签名”列表的操作列点击“签名”。内置驱动不提供此操作。
3. 首次使用点击“生成新密钥”，然后点击“下载私钥”保存 PEM 文件。生成的密钥为3072位RSA。
4. 已配置可信公钥时，点击“导入私钥”，选择与它对应的 PKCS#8 PEM 私钥文件。当前不提供在界面更换可信公钥的功能，以免使其他驱动签名失效。
5. 填写签名方，点击“签名并验证”。成功后，同一DLL包含的多个协议一起显示“已签名”，无需重新加载正在使用的驱动实例。

私钥只在浏览器中生成、导入和使用，不发送给网关，也不保存至浏览器存储。关闭弹窗或离开页面清除其界面引用。请自行保管下载的私钥；丢失后网关不能恢复。

浏览器签名依赖 Web Crypto。请通过HTTPS，或在网关电脑上通过localhost、127.0.0.1访问。普通HTTP局域网IP地址下会显示提示并禁用密钥操作。

签名针对当前DLL与清单中的版本信息。重新编译或升级改变DLL后，应重新签名。此功能与商业授权、Windows可执行文件签名、ZIP升级包签名不同。

## 强制验签开关

1. 打开“工业安全”。
2. 找到“协议驱动验签”卡片中的“强制协议驱动验签”开关。
3. 切换后立即保存并生效，无需重启。修改需要工业安全查看和证书管理权限。

按当前产品规则，开启时不预检查驱动，也不要求事先存在可信公钥。未签名、缺少可信公钥或签名验证失败的外部驱动直接禁用。内置驱动继续使用。

已加载的外部驱动在下一次连接、读写或订阅检查时执行新策略；被禁用的驱动不能继续发起读写，订阅更新停止接收，已有连接由设备执行队列清理。已经发到设备的请求不能撤回。签名通过或关闭强制验签后，设备按现有调度和重连策略恢复，不强制并发重建所有连接。

关闭后允许未签名驱动，但文件摘要不匹配或签名无效的驱动仍会被拒绝。启动时被强制验签拒绝的默认目录驱动，在关闭开关时重新扫描加载；如果列表未刷新，可点击刷新后再签名。

## 保存位置和配置优先级

- 应用配置 `Gateway:ProtocolDrivers:TrustedPublicKeyPem` 可以提供固定可信公钥；配置有值时优先使用它。
- 界面首次建立的公钥保存到 `Gateway:ProtocolDrivers:TrustedPublicKeyPath`。未配置此路径时，默认保存在升级数据目录的 `DriverTrust/public-key.pem`。
- 界面保存的强制验签策略位于上述公钥路径追加 `.policy.json` 的文件。它在启动时优先于 `Gateway:ProtocolDrivers:RequireSignature`，因此重启仍保留界面选择。没有策略文件时才使用应用配置的初始值。
- 驱动签名保存在DLL配套的 `.ipc-driver.json` 清单中。服务账户需要具备这些文件和信任目录的读写权限。
- 使用独立数据目录部署时，默认公钥及策略会随升级数据目录保存在该数据目录中。备份时应一并保留公钥、策略文件和签名清单。
