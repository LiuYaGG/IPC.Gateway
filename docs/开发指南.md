# 开发指南

## 环境与技术栈

- .NET 10 SDK、ASP.NET Core Minimal API、SqlSugar。
- Node.js、npm、Vue 3、TypeScript、Vite、Ant Design Vue、ECharts。
- 支持 SQL Server、PostgreSQL、MySQL、SQLite 配置存储。数据库地址按开发环境配置，不能假设与生产环境相同。
- 模型推理使用 ONNX Runtime；协议中的串口、OPC DA、ADS 等能力取决于目标平台及本机依赖。

## 打开项目与配置

在 Visual Studio 中打开根目录 `IPC.Gateway.slnx`；在 VS Code 中打开整个仓库目录。
主配置位于 `src/IPC.Gateway.WebHost/appsettings.json`，生产示例位于同目录 `appsettings.Production.example.json`。
本地开发时，将同目录的 `appsettings.Development.example.json` 复制为 `appsettings.Development.json`，填入本机数据库连接、密码及认证密钥。开发配置和生产配置均不纳入版本控制；示例文件不会自动加载。已有本地开发配置继续保留。
生产凭据放在现场配置或环境变量中；示例中的密码与密钥需要替换。已有系统迁移时保留原数据和显式加密主密钥。

主要配置段：`Gateway:Database`、`Gateway:Auth`、`Gateway:Security`、`Gateway:Runtime`、`Gateway:Mqtt`、`Gateway:OpcUa`、`Gateway:History`、`Gateway:Inference`、`Gateway:Scripting`、`Gateway:Watchdog`。
使用连接字符串时，需要预先创建对应数据库并赋予必要建表和读写权限。

## 安装依赖和构建

以下命令在仓库根目录执行：

```powershell
dotnet restore IPC.Gateway.slnx
Push-Location src/IPC.Gateway.Web
npm ci
npm run build
Pop-Location
dotnet build IPC.Gateway.slnx --no-restore
```

前端构建输出 `src/IPC.Gateway.Web/dist`，后端发布时复制到 `wwwroot`。
前端开发服务和后端可以分别启动：

```powershell
dotnet run --project src/IPC.Gateway.WebHost/IPC.Gateway.WebHost.csproj
```

```powershell
Push-Location src/IPC.Gateway.Web
npm run dev
Pop-Location
```

Vite 默认端口 5173，`/api` 代理目标在 `vite.config.ts`，当前为 `http://localhost:5184`。后端实际监听地址以启动输出为准。
浏览器访问后端时由后端直接提供已构建前端；访问 Vite 时使用开发热更新资源。

## 前端约定

- 生产入口 `src/IPC.Gateway.Web/src/main.ts`，主框架 `App.vue`。
- 设备、规则、历史、人员、权限等页面位于 `components`，通用输入和表格位于 `components/controls`。
- 中英文文本放在 `i18n`，新增标题、表头、提示和状态时补充两种语言。
- 数据值、PLC 地址和用户自定义名称保持原样，不翻译业务数据。
- 新建、编辑、写入使用居中弹窗；长表单按宽度调整列数。
- 数据表格使用公共分页，每页支持 20/50/100/200/500；操作列固定且不允许拖动宽度。
- 静默刷新不覆盖正在编辑的草稿；设备页面恢复树选择与滚动状态。
- 数组和字符串详情使用当前值抽屉。SSE 更新以最新状态为准，避免浏览器后台积压。

## 后端扩展

- 驱动接口与连接、读写、校验和批读能力保持一致。增加类型时同步驱动支持矩阵、序列化及界面。
- 采集任务按设备隔离；连接重试、超时和恢复探测不能拖慢其他设备。
- 配置更新走应用服务和仓储，避免界面绕过权限与审计直接修改数据库。
- 流程规则使用 FlowRules 类库，脚本使用 Scripting 类库，模型使用 Inference 类库。
- 设备写入是现场动作，开发排障不要对未知设备执行试写。

## 调试与维护

健康检查：`/health/live`、`/health/ready`；运行指标：`/metrics`（受现场权限配置约束）。
日志与错误详情可以从运行总览、设备标签、审计日志和售后快照查看。

离线维护工具的示例：

```powershell
dotnet run --project src/IPC.Gateway.Maintenance/IPC.Gateway.Maintenance.csproj -- reset-admin --password "新的现场密码"
```

维护工具的 `--config-dir` 必须指向目标系统的配置目录，否则可能连接错误的数据库。

仓库不再携带测试或模拟器代码；提交前至少构建前后端，并按 [发布验收清单](发布验收清单.md) 和 [浏览器验收清单](浏览器验收清单.md) 完成必要的人工验收。
