# 双机热备安装、更新与卸载

Windows、Linux 和 Docker 均部署三个角色。A、B 各运行一份带仲裁成员的业务网关，C 运行一个独立仲裁成员。正式运行时，整个集群有三个服务或容器。

| 节点 | Windows 服务 | Linux 服务 | 首次配置入口 |
| --- | --- | --- | --- |
| A、B，各自一台 | `IPCGateway` | `ipc-gateway` | 登录本节点网关，进入“系统 → 高可用” |
| C | `IPCGatewayArbiterC` | `ipc-gateway-arbiter-c` | 在 C 本机运行随包的“打开热备配置” |

### 发布前准备

1. 从完整源码运行 `script/windows/生成安装升级包.ps1`，选择 `-PackageType Install`，分别指定 `-RuntimeIdentifier win-x64`、`linux-x64` 或 `linux-arm64`。统信 UOS x64 glibc 2.28 另传 `-UosSqlitePackage` 指向经校验的兼容补丁包。Windows、Linux 均使用对应架构的 ASP.NET Core Runtime 10。Linux 安装脚本用到 Bash、systemd、Python 3、rsync 和 ACL 工具。
2. 将安装包解压到程序目录之外。以下命令从解压根目录执行。A、B 安装包的 `payload` 应包含 `IPC.Gateway.WebHost.dll`、`IPC.Gateway.Arbiter.dll`、`Drivers` 和 `wwwroot`。C 使用 `components/IPC.Gateway.Arbiter` 及独立配置向导。
3. A、B 各自准备有效的生产配置 `appsettings.Production.json`，使用相同的共享业务数据库和数据解密密钥。Windows 默认安装根下的位置是 `app\appsettings.Production.json`，Linux 默认是 `/opt/ipc-gateway/app/appsettings.Production.json`。配置数据库地址时，从另一台机器访问 SQL Server 请填可达地址。C 无需业务库。
4. 记录 A、B 各自的网关地址和 A、B、C 各自的仲裁地址。默认业务网关端口为 5184，仲裁客户端 HTTPS 端口为 7281，成员间 HTTPS 端口为 7282，B、C 配对时使用 HTTPS 7381。每台机器登记的地址需从其他节点可达。要实现宿主级故障切换，多数派、接管节点及其依赖的数据库需要能够在原主宿主掉线后继续工作。稳定业务 URL 由现场代理或虚拟 IP 提供。
5. 为每个角色准备专属的、本机持久化的身份目录，如 Windows 的 `E:\IPCGateway\ha` 或 Linux 的 `/etc/ipc-gateway/ha`。首次安装 A/B 可以使用空目录。安装器将该目录配置给网关服务账号，保存本机密钥、成员身份和仲裁状态。升级已有集成节点时必须使用其原目录及角色。

### 安装 A、B

Windows 管理员 PowerShell 示例（本机为 A）：

```powershell
.\tools\安装热备服务.ps1 -Role A -InstallRoot E:\IPCGateway -ConfigRoot E:\IPCGateway\ha -DataDirectory E:\IPCGateway\data -Url 'http://0.0.0.0:5184' -Start
Get-Service IPCGateway
```

Linux 示例（本机为 B，按实际替换 dotnet 和业务数据目录）：

```bash
sudo env DOTNET_PATH=/opt/dotnet10/dotnet INSTALL_DIR=/opt/ipc-gateway/app DATA_DIR=/var/lib/ipc-gateway SERVICE_URL=http://0.0.0.0:5184 START_SERVICE=1 bash ./tools/安装热备服务.sh B /etc/ipc-gateway/ha
systemctl is-active ipc-gateway.service
```

首次安装完成后登录 A、B 各自的管理网页。B 在完成组网并取得业务授权之前等待配置或待命。Windows 去掉 `-Start`、Linux 设置 `START_SERVICE=0` 可只注册本机服务。

**让首装的 A 在组网前立即采集。** 默认 A、B 都先提供管理界面。若现场明确由 A 唯一承担业务，可在 A 首次安装时，给上面的 Windows 命令加 `-StartAsStandalone`；在 Linux 上使用 `START_AS_STANDALONE=1 START_SERVICE=1` 并选择角色 A。这样启动后 A 可以正常采集，仍可在网页登记 B、C。确认现场没有其他运行中的业务主节点；复用现有共享数据库时先核对其中的业务任期和集群身份。曾取得正任期的集群应恢复原投票状态。

此选项限尚无网关及仲裁服务注册、旧 HA 身份或已登记端点、且本机身份目录为空的新 A。程序将一次性授权写入私有目录下的 `standalone-before-setup`。首次组网完成后，按本指南重启网关并启用集群。后续更新沿用原目录及管理方式，无需再次使用此选项。B 启动后始终等待组网及业务授权。

### 在界面组网，然后启动 C

1. 在 C 本机打开向导。Windows 可双击 `tools/打开热备配置.cmd`，自定义配置根目录时用 `.\tools\打开热备配置.ps1 -ConfigRoot E:\IPCGateway\ha`。Linux 执行 `sudo env DOTNET_PATH=/opt/dotnet10/dotnet bash ./tools/打开热备配置.sh /etc/ipc-gateway/ha`，按实际运行时路径调整。使用终端显示的完整本机链接，在 C 的浏览器登记角色 C 和两个仲裁地址，生成配对码，保持向导运行。
2. 登录 B，进入“系统 → 高可用”。填写 B 的业务网关地址和仲裁地址，生成 B 的配对码。
3. 登录 A，在“系统 → 高可用”填写本机地址、集群 ID、显示名称、稳定业务地址和首选节点。输入 B、C 各自的配对地址与短时配对码，生成组网配置。已有共享业务库的集群 ID 必须与库中登记的身份匹配；从旧部署迁移时同时核对业务任期。
4. 三台机器均写入配置后，关闭 C 的临时向导，执行 C 的安装入口。使用与向导相同的 C 配置根目录。以下按 C 的操作系统任选其一。

```powershell
.\tools\安装热备服务.ps1 -Role C -InstallRoot E:\IPCGateway -ConfigRoot E:\IPCGateway\ha -Start
Get-Service IPCGatewayArbiterC
```

```bash
sudo env DOTNET_PATH=/opt/dotnet10/dotnet START_SERVICE=1 bash ./tools/安装热备服务.sh C /etc/ipc-gateway/ha
systemctl is-active ipc-gateway-arbiter-c.service
```

5. 首次生成配置后，正常重启 A、B 两个网关服务各一次，加载新身份并启动各自的集成仲裁。Windows 管理员运行 `Restart-Service IPCGateway`；Linux 运行 `sudo systemctl restart ipc-gateway`；在 Docker 重启对应业务容器。重新登录 A，在“高可用配置”中保存草稿并执行“连接预检”。待三个成员通过后启用集群，核对仅有一个业务主节点，再测试手动切换与故障接管。

### 已有服务迁移及更新

- 维护前备份生产配置、业务数据库、环境文件、本机业务数据、各角色密钥和已停服成员的完整仲裁状态。已启用集群的持久身份绑定全部成员端点与已提交的业务任期。迁移时保持集群 ID、节点、已登记地址、各自 WAL 和网关状态一致；涉及改 IP 或遗失身份时，先评估恢复方案。使用空状态目录替换已运行的成员可能丢失投票历史并触发数据库任期冲突。
- 原部署为“业务网关 + 独立 A/B 成员”时，安装器遇到旧独立服务注册或容器会停止。先完成相应角色交接和备份，卸载旧 A/B 仲裁注册，确认独立实例不会重启。迁移旧向导生成的已有身份时，保留整个身份根及其中的向导完成标记、拓扑、身份文件、私钥、原仲裁日志、网关状态。确认专属根下的 `A` 或 `B` 子目录包含该角色的 `member.json` 和 `gateway-ha.json`，文件中的证书、状态、数据库与旧部署一致，网关服务账号可访问这些路径。旧部署的自定义环境变量和任期状态必须纳入迁移。安装器不会把旧独立服务的数据自动导入空身份目录。
- 更新已有集成 A/B 时，逐台转移业务，停该机的网关服务，使用相同的服务账号、原业务目录和原配置根重新安装。A/B 运行的仲裁随网关同步重启；保留另外两票可达。C 更新时只需更新独立仲裁。升级控制协议时，至少两个支持同一控制协议版本的成员上线后才能形成多数派。
- 原地替换已安装网关时，Windows 可传 `-PackageZip '<原始ZIP完整路径>'` 与实际的 `-UpdateDirectory`，Linux 对应 `PACKAGE_ZIP`、`UPDATE_DIR`。安装脚本在覆盖前核验原始 ZIP 并按已登记的信任记录继承驱动信任。使用与解压目录完全匹配的 ZIP。自行安装的插件和密钥从可信备份恢复。

### Docker

A/B 共用含集成成员的业务镜像，在各自宿主机启动一个持久化业务容器；C 使用仲裁镜像。源码构建 A/B 镜像可执行 `script/docker/发布仲裁客户端.sh --gateway-client <镜像名:版本>` 或对应 PowerShell 的 `-GatewayClient -Image`，交付环境先加载匹配版本的镜像。三个角色通过独立的环境文件登记镜像、挂载目录和端口。

下方为 A 或 B 的环境文件示例。生产配置放在宿主目录中的 `appsettings.Production.json`。该节点新生成的 HA 文件写入持久业务数据挂载的 `embedded-ha` 子目录，其他节点使用自己的独立数据目录。

```dotenv
IPC_HA_GATEWAY_IMAGE=ipc-gateway:release
IPC_HA_GATEWAY_CONFIG_DIR=/srv/ipc/gateway-config
IPC_HA_GATEWAY_DATA=/srv/ipc/data
IPC_HA_PEER_HISTORY=/mnt/peer/history
IPC_HA_PEER_COLD=/mnt/peer/history-cold
IPC_GATEWAY_HTTP_PORT=5184
IPC_ARBITER_CLIENT_PORT=7281
IPC_ARBITER_PEER_PORT=7282
IPC_HA_PAIR_PORT=7381
```

Docker 的 A 若需组网前采集，操作员应在初次启动前确认该节点全新、从未在已启用的集群中取得任期，并确认所有旧容器及业务实例已经退出。按照上述 `IPC_HA_GATEWAY_DATA=/srv/ipc/data` 示例，在宿主机的全新、专属数据目录内执行一次：

```bash
sudo bash -c 'set -euC; umask 077; mkdir -m 700 -- /srv/ipc/data/embedded-ha; printf A > /srv/ipc/data/embedded-ha/standalone-before-setup'
```

将示例改为实际数据路径；已有身份目录时此命令停止。A、B 均默认在没有该授权时等待组网。持续部署与容器启动入口应保留持久目录的实际状态。

C 使用向导写好的角色目录，容器内的配置、证书和状态路径必须匹配 `member.json`。举例：向导配置根为 `/etc/ipc-gateway/ha`，C 的仲裁状态目录为 `/etc/ipc-gateway/ha/C/raft`，环境文件可以写成：

```dotenv
IPC_ARBITER_IMAGE=ipc-gateway-arbiter:release
IPC_ARBITER_CONFIG_DIR=/etc/ipc-gateway/ha/C
IPC_ARBITER_MOUNT=/etc/ipc-gateway/ha/C
IPC_ARBITER_VOLUME=ipc-arbiter-c-state
IPC_ARBITER_CLIENT_PORT=7281
IPC_ARBITER_PEER_PORT=7282
```

新 C 容器将仲裁状态写入具名卷。已有 C 必须核对、迁移原状态后再启动。分别在各宿主机执行包内 `bash tools/docker/安装热备服务.sh A /srv/ipc/A.env`、`bash tools/docker/安装热备服务.sh B /srv/ipc/B.env` 或 `bash tools/docker/安装热备服务.sh C /srv/ipc/C.env`。Windows Docker Desktop 对应使用 `.\tools\docker\安装热备服务.ps1 -Role A -EnvironmentFile .\A.env`。升级前停止目标容器，确认镜像与当前安装包对应。

### 卸载服务

| 操作系统 | 操作 |
| --- | --- |
| Windows | 管理员 PowerShell 运行 `.\tools\卸载Windows服务.ps1 -ServiceName IPCGateway` 卸载业务节点；新装独立 C 指定 `IPCGatewayArbiterC`。旧同机部署可用 `-All` 注销本机全部标准网关和仲裁服务。 |
| Linux | 从完整包根目录运行 `sudo bash ./tools/卸载Linux服务.sh --gateway`。独立 C 用 `--arbiter`。旧同机部署可用 `--all`。卸载前用 `systemctl cat <单元名称>` 记录现场路径与环境。 |
| Docker | 使用原环境文件、原角色和同一项目，在统一安装命令最后加 `--uninstall`；PowerShell 使用 `-Uninstall`。 |

卸载入口保留现场程序、数据、证书、数据库和容器卷，以便迁移及重装。
