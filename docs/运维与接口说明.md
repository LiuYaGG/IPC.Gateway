# 运维与接口说明

## 健康与指标

| 地址 | 用途 |
| --- | --- |
| `/health/live` | WebHost 进程存活 |
| `/health/ready` | 运行时、队列、模块和存储的就绪情况 |
| `/api/health/ready` | API 就绪信息 |
| `/metrics` | 按现场配置及权限开放的运行指标 |

Nginx 反向代理和 Prometheus 参考文件位于 `docs/参考配置`。反向代理转发头需要配置可信代理边界，不能仅增加任意转发头。

## 主要接口与页面

配置、通道、设备、标签、规则等由 `/api/config` 管理；认证由 `/api/auth` 管理。
脚本和模型能力分别由对应模块接口提供。安装升级接口位于 `/api/maintenance/updates`。
售后快照汇总运行情况、健康检查和错误，查看内容受当前用户权限约束。

## OPC UA Server 安全配置

在“OPC UA Server → 安全”中分别选择消息安全模式和安全策略，然后保存。保存运行中的配置会重启 OPC UA Server，现有 OPC UA 客户端需要重新连接。

| 消息安全模式 | 可选安全策略 |
| --- | --- |
| None | None |
| 签名（Sign） | Basic128Rsa15、Basic256、Basic256Sha256、Aes128_Sha256_RsaOaep、Aes256_Sha256_RsaPss |
| 签名与加密（SignAndEncrypt） | Basic128Rsa15、Basic256、Basic256Sha256、Aes128_Sha256_RsaOaep、Aes256_Sha256_RsaPss |

切换到 None 时安全策略自动设置为 None；从 None 切换到签名或签名与加密时，默认选择 Basic256Sha256。客户端选择的模式和策略必须与服务端一致。上述加密策略沿用 RSA 应用证书；当前配置不提供 ECC 策略。

旧配置没有 `SecurityMode` 字段时，None 策略继续使用 None 模式，其他策略继续使用 SignAndEncrypt 模式。配置保存、备份与恢复均保留新字段，旧的布尔策略字段仅用于兼容旧配置。

“允许匿名访问”和“用户名密码登录”独立于消息安全模式。自动信任客户端证书只作用于服务端，客户端仍需按自己的配置信任服务器证书。启用用户名密码时，密码令牌采用所选的非 None 策略保护；None 通道则使用 Basic256Sha256 保护密码令牌，客户端需要支持该策略。

服务端按所选策略设置会话 nonce 长度。使用 Basic128Rsa15 签名模式及用户名密码时，如果客户端 SDK 固定要求 32 字节 nonce，可能报 `BadNonceInvalid`；客户端也需要按策略设置 nonce 长度（该策略为 16 字节），或双方改用 Basic256Sha256，不应关闭 nonce 校验。

## OPC UA 标签读写

标签的“读写权限”会同步到 OPC UA 节点的 `AccessLevel` 与 `UserAccessLevel`：可读可写标签允许读写，只读标签拒绝写入，只写标签允许写入并拒绝读取。模型计算的虚拟标签保持只读。修改标签配置后，运行中的 OPC UA Server 会重建节点，客户端需要重新连接并刷新节点属性。

OPC UA 写请求按通道、设备、分组和标签 ID 定位，通过统一运行时调用设备驱动，沿用启用状态、数据类型、值范围、元素数量、缩放和写后读回检查。驱动写入失败时向客户端返回失败，节点缓存不会只因收到写请求而显示新值；驱动写入成功但读回失败时，写操作仍成功，当前值质量由运行时快照反映。

支持标量和完整的一维数组写入，客户端必须发送与节点数据类型匹配的值。暂不支持通过 `IndexRange` 只写数组的部分元素，此类请求返回 `BadWriteNotSupported`，不会发送到设备。

## 证书状态与网站 HTTPS/TLS

工业安全页面的 OPC UA 证书清单读取网关当前生效的 OPC UA 配置，与 OPC UA Server 共用目录解析方法。相对路径以程序目录为基准，未填写目录时使用 `Data/OpcUa/pki`。Windows 服务环境变量只是启动默认值，数据库中保存的 OPC UA 配置可能覆盖这些默认值；排查时应以页面当前配置及清单显示的实际路径为准。

清单扫描证书目录下的证书文件，排除 `archive` 中的归档证书。目录不存在或没有证书时显示未配置，并提供目录和原因；证书无法解析时显示异常。已过期、即将过期和有效证书分别统计，证书的私钥状态由实际文件决定。

TLS 用于保护网络传输。在本项目中，工业安全页面的 TLS 条目检查网关自带 Web 服务的 HTTPS 证书，用于浏览器与网站/API 之间的加密通信、服务器身份校验和数据完整性保护。仅配置证书还需要同时配置 HTTPS 监听地址或端口，浏览器才能通过 HTTPS 访问。

网站 HTTPS/TLS 与 `opc.tcp` 的 OPC UA 安全配置独立：OPC UA 客户端连接由其消息安全模式、安全策略和 OPC UA 应用证书控制。已有 OPC UA 证书并不等于网站已有 HTTPS 证书；TLS 显示未配置也不表示 OPC UA 证书未配置。若 HTTPS 在 IIS 或 Nginx 终止，证书由该代理管理，网关本机 TLS 清单不会自动读取代理的证书配置。MQTT 的 TLS 开关和证书也单独配置。

## 排障顺序

1. 确认进程和监听地址，查看存活与就绪端点。
2. 检查数据库连接、磁盘空间和数据目录权限。
3. 查看设备状态、标签最近错误、驱动与协议连接参数。
4. 检查采集耗时、队列水位、恢复探测和外部服务状态。
5. Windows 查看服务和执行日志，Linux 查看 systemd 日志，Docker 查看容器日志。
6. 升级失败时核对版本、清单、摘要、程序写入权限和实际运行平台，保留错误日志后按平台流程回退。

单机看门狗不能代替双机热备。SQL Server 可用也不代表历史文件、MQTT 队列和现场设备均正常。
