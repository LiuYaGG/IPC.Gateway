# 运维与接口说明

## 健康与指标

| 地址 | 用途 |
| --- | --- |
| `/health/live` | WebHost 进程存活 |
| `/health/ready` | 运行时、队列、模块和存储的就绪情况 |
| `/api/health/ready` | API 就绪信息 |
| `/metrics` | 按现场配置及权限开放的运行指标 |

Nginx 反向代理和 Prometheus 参考文件位于 `docs/参考配置`。反向代理转发头需要配置可信代理边界，不能仅增加任意转发头。

## 主要接口与页面

配置、通道、设备、标签、规则等由 `/api/config` 管理；认证由 `/api/auth` 管理。
脚本和模型能力分别由对应模块接口提供。安装升级接口位于 `/api/maintenance/updates`。
售后快照汇总运行情况、健康检查和错误，查看内容受当前用户权限约束。

## 本地点位历史与磁盘占用

`Data/History/values-日期.jsonl` 保存当天的点位历史，每行对应一条历史记录。新记录省略与工程值相同的原始值、重复时间戳以及空的可选字段。查询既能读取已有的日文件，也能读取新产生的分卷和 gzip 归档。

“历史库 → 冷热分层与保留策略”提供两个独立的大小设置。

| 设置 | 作用 |
| --- | --- |
| 点位历史单文件分卷大小（MiB） | 默认 64。要让一个点位历史文件写到约 100 MiB 才换卷，填 100。系统在下一批写入前检查大小，上一批可能使文件略超阈值。 |
| 历史文件总容量上限（MiB） | 热目录和冷目录中的网关历史文件按文件大小合计，归档按压缩后大小计。填 100 表示自动清理时尽量将总量降到 100 MiB，填 0 表示不限总量。清理会优先删除最旧的历史文件，并保留当天正在写入的文件。维护间隔内或活动文件本身较大时，总量可以超过此上限。 |

如需封卷后立即安排压缩，打开“自动清理”“启用文件压缩”和“压缩热数据”，将“压缩等待天数”设为 0，然后点击“保存配置”。后台生成 `.jsonl.gz` 后移除原文件。压缩期间需要临时磁盘空间，压缩后的文件大小取决于历史内容。跨日文件也会按保留和压缩策略处理。

## 采集数据的对外字段

HTTP 使用 `GET /api/config/status/tags?deviceId=设备ID` 查询点位。响应的 `data` 是完整快照数组。SSE 的 `tags` 事件中，`data.tags[]` 使用相同的单点格式。两种协议都可按 `runtimeRevision` 判断快照新旧；接收新快照时应替换同一点的旧快照，避免残留上次的隔离或错误状态。

| 场景 | 接收方读取方式 |
| --- | --- |
| Web API、SSE、普通 MQTT 遥测 | 当前工程值读 `valueText`。原始值读 `rawValueText ?? valueText`，两者相同时省略前者。显式返回的空字符串是有效原始值。 |
| 点位诊断 | `quality` 与 `timestamp` 随快照返回。空错误、空清洗说明省略。HTTP/SSE 中缺少 `isTagIsolated`、`isStaticValidationError`、`cleaningApplied` 表示 false，缺少 `tagConsecutiveFailures` 表示 0，缺少 `nextTagRecoveryProbeTime` 表示未安排探测。最近实际读取错误仍读 `lastReadError`。 |
| 可选业务属性 | 已配置的单位、资产路径、业务类型、来源和非默认精度仍会输出；缺少 `precision` 表示使用默认精度。 |
| Web API 写入 | 继续检查 `data.success` 和 `data.currentValueText`。成功时可省略内层空的 `errorMessage`，失败时读取实际错误。 |
| 普通 MQTT 上下限报警 | `messageType` 为 `alarm` 或 `warning`，`transition` 为 `active` 或 `clear`。恢复消息沿用离开的报警或预警主题。用 `eventId` 去重，用 `value`、`threshold`、`direction`、`state` 和 `message` 读取数值和状态。 |
| 普通 MQTT 点位消息 | 用 `gatewayId` 关联状态主题中的 `gatewayName`、`siteName`、`configVersion`。心跳和状态主题分开时，队列积压、失败和重试等指标统一从 `gatewayStatus.mqtt` 读取；两者配置为相同主题时，心跳继续携带这些指标。 |
| 规则 MQTT 消息 | 触发和恢复统一读 `eventType`（`active` / `clear`），自定义文本读 `message`。`messageType=ruleEvent` 已标明来源，原有 `action` 和固定的 `source=RuleEngine` 省略。`sourceValues[]` 中 `role=trigger` 的点位 ID、名称、编码、单位和质量取顶层字段，采样时间和原始值仍取该来源项。其他来源项保留自己的身份和质量。 |

普通 MQTT 遥测示例（主题 `ipc/data/西门子通道/西门子PLC/_/运行状态`）：

```json
{
  "messageType": "telemetry",
  "protocolVersion": "ipc.gateway.v1",
  "gatewayId": "IPC-Gateway-Web",
  "channelId": "ch-01", "channel": "西门子通道",
  "deviceId": "plc-01", "device": "西门子PLC",
  "groupId": "", "group": "",
  "tagId": "run-01", "tag": "运行状态",
  "pointCode": "LINE1.RUN", "dataType": "Bool",
  "valueText": "True", "quality": "Good",
  "timestamp": "2026-11-12T10:20:30.0000000+08:00"
}
```

本例的原始值也是字符串 `"True"`。升级前已进入 MQTT 发件箱的消息按入队时的格式发送，消费端可能先后收到两种格式。上述 JSON 约定适用于普通 MQTT 点位和规则事件；Sparkplug B 数据主题继续使用其 Protobuf 结构。

## 报警记录与断线补发

在“设备管理”中给数值标签启用上下限报警。例如上限为 80、预警偏差为 0，依次读到 75、82、84、78 时，会记录 82 触发高限报警和 78 恢复正常两条事件。断线期间读到坏质量会保留上次报警状态，取得有效采样后再判断恢复。

在“历史库 → 报警记录”查看事件时间、标签或规则、状态变化、触发值、阈值和发送状态。关闭普通点位历史后仍可查看新报警。具有历史查看权限的账号也可调用 `GET /api/config/history/alarms?page=1&pageSize=20` 分页查询，响应包含 `data.total` 和从新到旧排列的 `data.items`。

“仅本地记录”表示事件已存档。“待发送”表示事件已登记 MQTT 投递，断线或网关重启后仍可补发。“已发送”表示 Broker 已确认接收。若确认报文在途中丢失，订阅方可能再次收到相同的 `eventId`，应使用此标识去重。MQTT 页面分别显示报警和普通消息的待发数量与最早等待时间。

在规则引擎的“MQTT 发布”节点打开“报警消息”，该输出的触发和恢复会进入报警记录。如需两种消息都对外发布，同时开启节点的恢复发布。普通 MQTT 的“合并积压点值”默认关闭，打开后同一标签、同一主题的待发遥测保留最新值。报警和规则事件仍逐条保存。

## OPC UA Server 安全配置

在“OPC UA Server → 安全”中分别选择消息安全模式和安全策略，然后保存。保存运行中的配置会重启 OPC UA Server，现有 OPC UA 客户端需要重新连接。

| 消息安全模式 | 可选安全策略 |
| --- | --- |
| None | None |
| 签名（Sign） | Basic128Rsa15、Basic256、Basic256Sha256、Aes128_Sha256_RsaOaep、Aes256_Sha256_RsaPss |
| 签名与加密（SignAndEncrypt） | Basic128Rsa15、Basic256、Basic256Sha256、Aes128_Sha256_RsaOaep、Aes256_Sha256_RsaPss |

切换到 None 时安全策略自动设置为 None；从 None 切换到签名或签名与加密时，默认选择 Basic256Sha256。客户端选择的模式和策略必须与服务端一致。上述加密策略沿用 RSA 应用证书；当前配置不提供 ECC 策略。

旧配置没有 `SecurityMode` 字段时，None 策略继续使用 None 模式，其他策略继续使用 SignAndEncrypt 模式。配置保存、备份与恢复均保留新字段，旧的布尔策略字段仅用于兼容旧配置。

“允许匿名访问”和“用户名密码登录”独立于消息安全模式。自动信任客户端证书只作用于服务端，客户端仍需按自己的配置信任服务器证书。启用用户名密码时，密码令牌采用所选的非 None 策略保护；None 通道则使用 Basic256Sha256 保护密码令牌，客户端需要支持该策略。

服务端按所选策略设置会话 nonce 长度。使用 Basic128Rsa15 签名模式及用户名密码时，如果客户端 SDK 固定要求 32 字节 nonce，可能报 `BadNonceInvalid`；客户端也需要按策略设置 nonce 长度（该策略为 16 字节），或双方改用 Basic256Sha256，不应关闭 nonce 校验。

## OPC UA 标签读写

标签的“读写权限”会同步到 OPC UA 节点的 `AccessLevel` 与 `UserAccessLevel`：可读可写标签允许读写，只读标签拒绝写入，只写标签允许写入并拒绝读取。模型计算的虚拟标签保持只读。修改标签配置后，运行中的 OPC UA Server 会重建节点，客户端需要重新连接并刷新节点属性。

OPC UA 写请求按通道、设备、分组和标签 ID 定位，通过统一运行时调用设备驱动，沿用启用状态、数据类型、值范围、元素数量、缩放和写后读回检查。驱动写入失败时向客户端返回失败，节点缓存不会只因收到写请求而显示新值；驱动写入成功但读回失败时，写操作仍成功，当前值质量由运行时快照反映。

支持标量和完整的一维数组写入，客户端必须发送与节点数据类型匹配的值。暂不支持通过 `IndexRange` 只写数组的部分元素，此类请求返回 `BadWriteNotSupported`，不会发送到设备。

## 证书状态与网站 HTTPS/TLS

工业安全页面的 OPC UA 证书清单读取网关当前生效的 OPC UA 配置，与 OPC UA Server 共用目录解析方法。相对路径以程序目录为基准，未填写目录时使用 `Data/OpcUa/pki`。Windows 服务环境变量只是启动默认值，数据库中保存的 OPC UA 配置可能覆盖这些默认值；排查时应以页面当前配置及清单显示的实际路径为准。

清单扫描证书目录下的证书文件，排除 `archive` 中的归档证书。目录不存在或没有证书时显示未配置，并提供目录和原因；证书无法解析时显示异常。已过期、即将过期和有效证书分别统计，证书的私钥状态由实际文件决定。

TLS 用于保护网络传输。在本项目中，工业安全页面的 TLS 条目检查网关自带 Web 服务的 HTTPS 证书，用于浏览器与网站/API 之间的加密通信、服务器身份校验和数据完整性保护。仅配置证书还需要同时配置 HTTPS 监听地址或端口，浏览器才能通过 HTTPS 访问。

网站 HTTPS/TLS 与 `opc.tcp` 的 OPC UA 安全配置独立：OPC UA 客户端连接由其消息安全模式、安全策略和 OPC UA 应用证书控制。已有 OPC UA 证书并不等于网站已有 HTTPS 证书；TLS 显示未配置也不表示 OPC UA 证书未配置。若 HTTPS 在 IIS 或 Nginx 终止，证书由该代理管理，网关本机 TLS 清单不会自动读取代理的证书配置。MQTT 的 TLS 开关和证书也单独配置。

## 排障顺序

1. 确认进程和监听地址，查看存活与就绪端点。
2. 检查数据库连接、磁盘空间和数据目录权限。
3. 查看设备状态、标签最近错误、驱动与协议连接参数。
4. 检查采集耗时、队列水位、恢复探测和外部服务状态。
5. Windows 查看服务和执行日志，Linux 查看 systemd 日志，Docker 查看容器日志。
6. 升级失败时核对版本、清单、摘要、程序写入权限和实际运行平台，保留错误日志后按平台流程回退。

单机看门狗不能代替双机热备。SQL Server 可用也不代表历史文件、MQTT 队列和现场设备均正常。
