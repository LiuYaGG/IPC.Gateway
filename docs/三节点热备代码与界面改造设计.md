# 三节点热备代码与界面改造设计

**开发设计稿 · 2026-11-23**。本设计落实[三节点热备与防双主实施方案](三节点热备与防双主实施方案.md)。A、B 运行网关，A、B、C 各运行一个独立仲裁成员。业务切换和具体 PLC 写授权共享一条多数派提交日志。最终用户在新页面 **系统 → 高可用** 查看和操作热备；无需进入仲裁成员自己的管理网站。

## 一、工程依赖与配置

## 二、仲裁状态机和业务生命周期

**状态字段。** 仲裁快照保存集群身份、当前业务主节点与进程实例、业务任期 `epoch`、租约版本、维护状态、在办切换、命令去重记录及提交位置 `commitIndex`。业务任期与 Raft 选举任期分开。每次服务重启都生成新的 `instanceId`。序号在 C# 用 64 位整数，在浏览器 JSON 中传十进制字符串，避免脚本整数精度损失。

| 状态机命令 | 校验及提交后的效果 |
| --- | --- |
| `GrantOwner / RenewOwner` | 检查候选资格、实例、任期及租约版本。只有业务进程能续自己的租约，独立仲裁进程不能替挂起的网关续约。 |
| `BeginHandover / ConfirmDrained / TransferOwner` | 核对预期任期、源与目标、目标配置版本和操作 ID。停收旧主新写后清理可取消任务；旧主确认已退出可提前切换。旧主消失时安全等待租约到期，B 已就绪且有多数即可自动接管。并发管理员操作复用同一在办操作或返回冲突。 |
| `PermitWriteAttempt` | 在同一状态机的当前提交顺序下，校验主节点、实例、任期、租约与具体命令摘要。授权在日志中的索引决定是否早于切换。 |
| `SetMaintenance` | 只允许按预期版本进入或退出维护；主机仍承载业务时先交接。集群已缺一票时，升级或停止第二个投票成员的预检必须失败。 |

授主和写许可客户端都使用 mTLS。每个请求带唯一操作 ID；重传同一请求只返回原决定，相同 ID 携带不同内容返回冲突。快照保留去重窗口和拒绝旧序号所需的水位。旧领导者的本地缓存、未提交日志和普通心跳都不能作为授权。领导者更换后从已提交状态恢复，无法确定旧租约到期时保守等待安全窗口。以 1 秒续约、5 秒租约作为联调初值，最终按压测确定。

**宿主改造。** 在 [GatewayRuntimeHostedService](../src/IPC.Gateway.WebHost/GatewayRuntimeHostedService.cs) 拆开“管理面就绪”和“业务面激活”，在 [GatewayCoreService](../src/IPC.Gateway.Core/Gateway/GatewayCoreService.cs) 提取预热、激活、交接排空、失主停用四个操作，保留单机启动入口。协调器串行处理角色变化、热重载和看门狗恢复。每个已激活实例有独立任期取消令牌，重建时创建新任务生命周期，避免重复订阅或重复启动后台线程。

- **备机预热**加载权威项目、校验插件签名和版本、预编译脚本、核对证书与必要业务数据，可独立登录。备机只报告 readiness，不连接 PLC 或发布业务消息。
- **升主**先核对配置版本与可接管状态，再绑定新任期，恢复未闭环报警和关键待发记录，分设备建立连接。网页分开显示“已获授权”“业务入口已就绪”“收到首个有效样本”；个别设备离线不阻塞其他设备。
- **计划交接**停收新的 PLC 写和配置变更，标记已发未确认操作，关停旧任期的生产者及逻辑连接。**失主降级**立即关闭对外动作入口，停止脚本数据库队列、规则延时动作和 MQTT 待发消费，不调用会继续发送积压的退出路径。[MQTT 服务](../src/IPC.Gateway.Core/EdgeGateway/MqttGatewayService.cs) · [脚本数据库队列](../src/IPC.Gateway.Scripting/Database/ScriptDatabaseWriteDispatcher.cs)
- **配置及恢复**将保存项目、重载规则、恢复备份、MQTT 远程配置以及 [看门狗](../src/IPC.Gateway.Watchdog/GatewayWatchdogHostedService.cs) 的直接重启改为向协调器请求。持久化配置按期望版本比较更新，跨进程的数据库迁移使用业务库自己的互斥机制。SQL 保持业务存储职责。

## 三、PLC 写调用链的改动

配置和报警办理等共享库写入还需要数据库内的任期保护。B 得到业务任期后，先在业务库安装新任期，再开放配置写入及人工办理；写事务同时核对期望版本和业务库任期。仲裁提交和业务库事务可分别成功或失败，管理页应能显示“已授主，业务库尚未就绪”。PLC 写授权边界仍以仲裁提交位置为准。

现有 Web API、脚本标签写、MQTT 下行和 OPC UA 标签写大多会汇入运行时；协议诊断另外创建驱动客户端。实施时要验到真正产生 PLC 写效果的那一层。

| 修改位置 | 要写的代码 |
| --- | --- |
| [运行时设备写队列](../src/IPC.Gateway.Core/Engine/RuntimeEngine.Configuration.cs)、[实际驱动调用](../src/IPC.Gateway.Core/Engine/RuntimeEngine.cs) | 保留目标解析、设备 Actor、通道排队与配置代数校验。将现有同步 `beforeDispatch` 扩展为可取消的异步执行路径，覆盖字符串、带元素数的写入、异步及同步驱动。队首准备完成后再申请授权，授权返回后复核目标配置；目标已变则丢弃本次许可。禁止在同步全局锁内等网络。 |
| [协议诊断](../src/IPC.Gateway.WebHost/ProtocolDiagnosticRunner.cs) | 临时设备也经过同一个授权执行器，摘要绑定真实协议、地址、连接目标和写值。连接或读取测试转到业务主机执行；仅编辑测试参数和纯离线校验可在备机进行。 |
| [驱动能力](../src/IPC.Gateway.Core/Core/PlcClientCapabilities.cs)、[Modbus TCP 适配器](../src/IPC.Gateway.Core/ModbusTcp/NModbusMasterAdapter.cs) | 在既有插件 ABI 之外增加可选的热备写能力契约。单发驱动由调用边界申请一次，内部分片或重试的驱动为每个能产生写效果的子操作申请一次。记录已确认片数及结果未知片。存量插件需要经过能力验证后才能启用热备写入。 |

建议的核心契约如下，名称为拟新增标识。

```csharp
ValueTask<WritePermitDecision> AuthorizeAsync(
    PlcWriteAttempt attempt, CancellationToken cancellationToken);
```

`PlcWriteAttempt` 包括 `clusterId/nodeId/instanceId/epoch`、逻辑命令 ID、尝试 ID、目标配置版本、指令内容摘要及片序号。摘要涵盖协议、实际目标、地址、类型、长度、偏移和编码后的写入内容。日志显示脱敏描述及摘要，不记录设备凭据。

**本地发送规则。** 同一尝试只允许一个执行者。授权批准后持久记录“准备下发”，再调用驱动；进程从这两步之间崩溃会留下“结果未知”，不能推断为成功，也不能由新进程自动补发。授权 RPC 超时可查询同一尝试；查询操作本身绝不发包。设备结果不明的非幂等命令禁止自动重试。正常业务重试需要新的尝试 ID 和新的多数派授权。本地拒绝、授权超时、旧任期和驱动未准入分别归为网关原因，不应触发设备离线、坏点隔离或 PLC 重连。

**验收分界。** 若日志 410 批准了 A 的具体尝试，411 提交 B 接管，410 允许按原约定完成一次。A 在 411 后的所有新尝试均不得获批。审计同时记录授权决定与设备执行结果。无多数时被本地拒绝的请求没有提交索引，界面应显示“—”，保留尝试 ID 与本地证据来源。

## 四、管理 API、权限和实时更新

保留既有 `/api/config/tags/write` 和 `/api/diagnostics/protocol/run` 路由及单机成功响应。在 [配置端点](../src/IPC.Gateway.WebHost/GatewayConfigurationEndpoints.cs) 和 [诊断端点](../src/IPC.Gateway.WebHost/ProtocolDiagnosticEndpoints.cs) 显式映射授权拒绝、命令冲突及设备结果，保证 HTTP 状态和操作审计一致。热备新增请求头支持逻辑命令 ID 与界面确认时的预期任期；旧客户端无 ID 时由服务端生成并随结果返回，不对非幂等请求做透明重发。

以下路径为拟新增的 WebHost 管理接口，与成员之间的内部授权 API 分离。浏览器只拿操作许可和脱敏状态，不能申请 PLC 写令牌。

| 接口 | 权限 | 契约 |
| --- | --- | --- |
| `GET /api/ha/status` | `ha.view` | 返回模式、接入节点、本机角色、业务主机、任期、可达成员数、观测时间、信息是否过期、成员列表、备机阻塞原因和本账号可用的操作。无多数时仍可返回本机带时间的观测。 |
| `POST /api/ha/switchovers/precheck` | `ha.switchover` | 只读预检，输入目标与预期任期，返回当前主机、目标实例、配置修订、阻塞项和提示。预检结果不能当作最终切换授权。 |
| `POST /api/ha/switchovers`、`GET /api/ha/switchovers/{id}` | 发起用 `ha.switchover`，查看用 `ha.view` | 提交操作 ID、目标、预期任期和原因。服务端在提交时重新校验，返回 202 和操作 ID。重复提交、浏览器刷新、SSE 重连均追踪原操作。 |
| `GET /api/ha/switchovers`、`GET /api/ha/write-attempts` | `ha.view`、`ha.writes.view` | 服务端时间范围、节点与结果筛选、分页；区分提交索引、逻辑命令、尝试、来源、设备地址和实际结果。涉及写明细的 DTO 按既有数据访问范围裁剪。 |
| `POST /api/ha/maintenance` | `ha.maintenance` | 提交节点、目标维护状态、期望版本和原因。进入维护不会自行停服务或绕过升级权限。 |
| `GET /api/ha/config`、`PUT /api/ha/config/draft` | 读取用 `ha.view`，编辑用 `ha.config.manage` | 查询脱敏的当前配置、生效版本和节点应用状态；保存草稿返回草稿 ID、版本及字段校验结果，不影响运行。首次组网草稿归显示的管理节点所有，可重新打开。 |
| `POST /api/ha/config/precheck`、`POST /api/ha/config/apply` | `ha.config.manage` | 预检绑定草稿版本、内容摘要及 A/B/C 身份；应用时带期望生效版本、预检 ID 和幂等操作 ID，再次核实前置条件。初始化走一次性组网流程，在线策略修改经多数派提交。返回操作 ID，可查询每个节点的接收、应用或等待状态。 |
| `GET /api/ha/config/operations/{id}` | `ha.view` | 页面刷新后按操作号找回组网或策略应用进度，返回逐节点结果、生效版本及阻塞原因，隐藏登记凭据和私钥。 |

沿用 `success/data` 和 `errorCode/errorMessage`。未登录返回 401，缺权限为 403，已知备机写入或任期变化为 409，目标未就绪为 409，无法取得多数派为 503。已进入驱动、结果不明时返回尝试 ID 与 `Unknown` 结果，不能包装成“重试即可”的普通故障。管理页面首次读取的局部事实和全局权威事实分开，例如：

```json
{
  "success": true,
  "data": {
    "mode": "Cluster", "connectedNode": "A", "localRole": "Demoted",
    "authority": "LocalLastKnown", "owner": null, "lastKnownOwner": "A",
    "lastKnownEpoch": "17", "reachableMembers": 1, "memberCount": 3,
    "canStartSwitchover": false, "reasonCodes": ["HA_NO_QUORUM"]
  }
}
```

增加充足但最小的本机会话能力摘要，允许已登录用户看到“本页当前只读”和原因；集群拓扑、节点地址、切换记录和命令明细分别鉴权。权限接入 [后端权限目录](../src/IPC.Gateway.Core/Domain/Users/GatewayPermissionCatalog.cs)、[前端权限常量](../src/IPC.Gateway.Web/src/utils/permissions.ts) 和角色分配页。HA 权限不授予 PLC 写权限，拥有 PLC 写权限也不能绕开多数派。

在 [启动状态中间件](../src/IPC.Gateway.WebHost/GatewayStartupState.cs) 放行经现有认证的本机 HA 状态和操作查询，不把健康备机长期暴露为“网关正在启动”。状态读取应能脱离 PLC 运行时；业务登录库不可用时，只保留最小的健康探针，不开放未认证管理接口。

运行推送包含新事件 `haChanged`；运行值事件带业务任期和流实例 ID。复用 [GatewayRuntimeEventHub](../src/IPC.Gateway.WebHost/GatewayRuntimeEventHub.cs) 的快照水位与有界队列，把 HA 状态按最新值合并。切主时客户端取消旧订阅、清空旧运行水位、接收新主快照后再应用增量，丢弃晚到的旧任期事件。切换记录和逐笔授权由持久查询提供，不把每笔写推给所有浏览器。SSE 不可用时，仅已打开的 HA 页低频查询状态；页面停用或账号变更时取消订阅与请求。

| **切换记录** | 按时间、节点、计划或故障切换、结果筛选。展示操作人或自动触发原因、源和目标、前后业务任期、提交位置，以及检测、授主、业务就绪、首样本各自耗时。仅有真实进度才推进步骤。 |
| **PLC 写授权** | 独立权限和按需查询。列表展示本地时间、节点、任期、目标、来源、授权结果和设备结果。行详情展示命令/尝试 ID、提交索引、分片、重试与脱敏内容摘要。“已授权 / 结果未知”“无多数 / 未下发”必须能区分。 |
| **高可用配置** | 未组网时提供三步向导；已组网时显示生效配置、待应用差异、最后修改人及 A/B/C 的应用进度。有查看权限可读，具有配置权限才可编辑、预检和应用。 |

### 高可用配置页

1. **填写集群与节点。** 管理员打开 A 或 B 的网站一次录入集群名称、稳定业务访问地址和 A/B/C 三行节点信息。每行填写主机名或 IP、仲裁管理端口、成员通信端口，选择安装时登记的节点身份及证书引用。A/B 另填网关管理地址并选择首选主机；C 的业务地址留空。集群 ID 首次自动生成，已有节点加入时校验同一 ID。Windows 服务、systemd 和 Docker 使用相同的表单；Docker 填写其他宿主可达的公告地址。
2. **预检。** WebHost 联系三个已登记的仲裁端，各端分别检查成员间双向连通、身份与证书对应、持久目录可写、已有集群归属和版本兼容性。A/B 额外核对项目版本、驱动、业务凭据和备机就绪情况。结果逐节点列明哪一侧无法连接、哪个端口或身份不匹配。修改关键字段会使旧预检失效。安装时通过受信证书或受保护的一次性登记凭据建立初始信任，网页只显示证书名称、指纹、到期日，不收集私钥。
3. **确认并启用。** 草稿保存期间原网关照常工作；启用前弹窗显示首任候选、可能暂停的写入及变更范围。若 A/B 原来以单机运行，先预置并持久化“切换至集群后启动默认待命”的配置，在两台停收单机写入并回执后才开放首次集群授权。三端对同一引导清单确认，禁止并发向导独立建出两个集群。部分下发失败时保留操作号、显示已完成步骤，重试沿用原清单；已退出单机的实例不会自行恢复单机写权限。

| 已组网的字段或操作 | 生效方式 |
| --- | --- |
| 集群显示名称、首选业务节点 A/B | 管理员可改，按版本提交；首选只用于两台均可首次授主等候选决策。修改首选不触发抢占，需要立即换主时走“计划切换”。 |
| 续约间隔、业务租约时长 | 单位明确，预填联调初值 1 秒/5 秒。后端验证正值、允许范围及续约间隔与租约之间的安全余量。显示“当前值 → 新值”；新策略在兼容检查完成后的续约/新授主生效。已确认的旧租约不能因调短超时而提前失效。 |
| 稳定业务地址 | 显示当前值并可预检新入口；应用前现场应已配置相应 DNS、代理或虚拟 IP 及证书。保存网址只更新网关引用，不会在外部设备上自动创建该入口。 |
| 集群 ID、固定成员身份、票数、节点私钥与持久目录 | 在线配置中只读。更换机器、成员通信地址或证书使用显式维护和逐节点验证；两票门槛属于三成员部署协议，不提供调整开关。 |

配置界面区分“已保存草稿”“多数派已提交”“各节点已应用”。已有集群失去多数派时展示带时间和来源的最后生效值，禁用在线应用；已提交版本在恢复联系后补同步。仅修改管理策略无需重启业务。任期变化、并发版本冲突、目标未就绪和证书失效分别给出中英文原因。配置权限、计划切换权限及 PLC 写入权限独立授权，配置变更按差异写入审计，记录操作者、时间、版本和操作 ID。

**计划切换弹窗。** 使用居中 Ant Design Modal。先预检目标，展示“当前 A → 目标 B”、版本、未完成写入、当前任期与阻塞原因，再填写原因并确认。预检通过才可提交，409 时刷新预检。提交以后可以关闭弹窗，后台按同一操作 ID 继续；再次进入仍能看进度。业务地址在切换中短暂断开时显示“正在重新连接，操作号……”，先查询最终状态，前端不重发切换或写入。已经授予 B 后发生错误，显示当前 B 所在阶段，后续回切是另一笔操作。

**按状态展示。** 单机模式显示“尚未组网”，有配置权限时提供“开始配置”入口直达第四个页签，隐藏计划切换控件。已知备机可看本机管理并通过经过校验的稳定业务入口访问活动主机；失去多数时显示“无法核实当前主机，新 PLC 写入已禁止”。具备权限但因状态不可用的按钮置灰并在附近显示原因；无权限操作隐藏。主机切换不自动重发写命令或提交未保存表单。

**现有页面的影响。** 设备管理的写入、协议诊断的在线操作、点表在线抽样、脚本调试的写动作分别复用能力提示；离线编辑草稿、离线点表检查可用。配置保存与报警办理遵守后端写入策略。安装升级增加目标主机和剩余健康票数预检；Windows 执行服务升级、Linux 展示宿主脚本方式、Docker 展示镜像方式。全局顶栏在集群模式只显示紧凑的本机角色状态，按权限链接到高可用页。

前端接线需覆盖四处容易遗漏的路径：

1. `App.vue` 的会话初始化和实时订阅目前依赖业务快照。高可用页单独获取已授权会话和 HA 状态，使仅具备 HA 查看权的用户也能进入；接入点位推送时，再将快照及事件按 `clusterId + epoch + sourceInstanceId` 分组。[实时流解析](../src/IPC.Gateway.Web/src/utils/runtimeStream.ts) · [推送状态](../src/IPC.Gateway.Web/src/utils/runtimePush.ts)
2. [设备管理](../src/IPC.Gateway.Web/src/components/DevicesView.vue) 的 `canWriteTag` 与 [协议诊断](../src/IPC.Gateway.Web/src/components/ProtocolDiagnosticsView.vue) 的 `confirmWrite` 在打开弹窗和确认时分别检查权限、能力与任期。提交前任期变化时保留输入、撤销旧确认；已经提交而请求断开则按尝试 ID 查询。
3. 角色分配复用 [权限显示映射](../src/IPC.Gateway.Web/src/utils/display.ts) 与服务器权限目录。公开健康探针只返回最小健康信号；成员拓扑、操作者和命令明细只通过相应权限的管理 API 展示。
4. 后端分页的授权与切换记录只切一次页。在 [GatewayTable](../src/IPC.Gateway.Web/src/components/controls/GatewayTable.vue) 关闭表内二次分页，使用共享分页控件绑定服务器总数；切换筛选回到第一页，记录结果保持同一查询快照。

**响应式与语言。** 使用现有 Ant Design Vue、图标、字体和表格组件。宽屏三项摘要同排，筛选项尽量单行；窄屏摘要重排、筛选换行，节点详情和弹窗内容可滚动。记录表填满剩余高度，表体独立横纵滚动，操作列固定、宽度不可拖动。分页固定在底部，继承 20/50/100/200/500 条、跳转和本页/总条数。本地时间用于展示，服务端传 UTC。中英文同时覆盖状态、错误、权限描述和切换原因，节点名、设备名、审计原文保留。切出页面保留筛选、页签和分页；身份切换时清理上一账号数据。

## 六、提交顺序和验收门槛

| 开发批次 | 应有交付 | 合入前验证 |
| --- | --- | --- |
| 1. 仲裁与配置 | 两个工程、协议契约、三成员启动脚本、持久化状态机 | 并发申请只有一位业务主机；两票成功、一票拒绝；快照后重启保留去重；只换仲裁领导者不引发 PLC 重连。 |
| 2. 生命周期与组网页面 | 备机预热、看门狗角色门控、健康与配置 API、独立页面、权限与首次组网向导 | 单机可保存草稿且不影响采集；错地址、重复身份与跨集群节点在预检中可定位；下发中断、并发启用能按操作 ID 恢复；C 无需网站；无配置权限不能应用，无多数不能在线改策略；缩短租约不提前授主。 |

| 4. 接管与业务接续 | 计划与故障切换、操作查询、报警和关键队列接续、SSE 新快照与旧流丢弃 | A 突然断电、业务进程挂起、只失去仲裁网络而 PLC 仍可达三种情况均测试；另测 A 不可见 B/C 时页面显示未知、重复点击、页面刷新和响应丢失。 |

前两批先交付可观察的待命与仲裁能力。驱动准入、关键状态接续和故障压测通过后，才将“故障自动切换可用于生产”的能力列入版本说明。
