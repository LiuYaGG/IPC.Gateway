# Linux 网页升级与平台兼容检查

本次更新需要先通过完整安装包更新 Linux 服务定义，安装独立更新辅助器。只复制网关 DLL 不会给旧服务增加网页重启权限。A/B 仍各只运行一个网关进程，更新辅助器仅在执行更新时运行；C 仍是独立见证成员。

## ZIP 中文名与目录分隔符

新版打包器显式使用 UTF-8 文件名和 ZIP 标准正斜杠路径，兼容 Windows PowerShell 5.1 与 PowerShell 7。旧包如果在 Linux 下出现名称为 `tools\docker\安装热备服务.sh` 的平铺文件，说明反斜杠被作为文件名字符；这不是少了一个 tools 目录，不能直接在原目录继续安装。

对旧包，可使用源码中的 `script/linux/解压安装升级包.py`，传入原 ZIP 和一个新的空目录。它在解压时转换分隔符，保留每个文件的原始字节，不重新压缩、不修改清单或签名。安装时 `PACKAGE_ZIP` 仍指向原始 ZIP。不要删除原 HA 配置，也不要将平铺文件批量移动进正在运行的程序目录。

默认新清单为版本 3，签名规范增加了兼容字段。为让旧 Windows 网页完成首次升级，打包脚本提供显式 `-LegacyUpgradeManifest` 过渡选项，使用旧版本 2 签名规范，同时保留新兼容字段与 payload 描述。描述文件仍受文件摘要和发布签名保护，新服务执行前必须将其与清单的兼容字段严格比对。此选项仅用于旧版本首跳，默认仍使用版本 3。B 首次仍需要通过完整包安装 systemd 辅助器；以后新版本之间可正常使用网页升级。

## 安装已有 B 的辅助器

1. 用 Windows 打包脚本选择 `linux-x64` 生成完整包，统信 glibc 2.28 使用已验证的兼容库选项；脚本会在替换兼容库后扫描目标架构 ELF 的 GLIBC 符号要求。
2. 保留 B 的生产配置、业务加密密钥和专属 HA 目录，并备份共享业务库。确认三节点健康，把 B 置于维护状态后停止 B 网关。
3. 将完整包解压到单独目录，使用包内新版“安装热备服务.sh”，沿用 B 原来的角色、ConfigRoot、数据目录、服务名和 .NET 路径。脚本会更新网关服务定义，同时安装 root 拥有的更新组件、固定配置和 systemd 请求监视单元。
4. .NET 安装程序及其上层目录必须由 root 拥有且不可被组或其他用户写入；否则辅助器不会安全安装。不得用开放 sudo 权限或关闭主服务的 NoNewPrivileges 代替此步骤。
5. 启动 B，检查安装升级页。辅助器未安装、监视单元未运行或在 Docker 中时，执行按钮不可用并显示原因。

普通单机使用新版“发布Linux服务.sh”安装，完整包内必须包含 `components/IPC.Gateway.UpdateWorker`。更新探针默认使用 `SERVICE_URL` 的实际端口；多监听地址或特殊映射时，通过 `UPDATE_HEALTH_URL` 明确提供对应本机回环启动状态地址。

## 日常网页升级

直连目标网关管理地址，上传匹配平台 ZIP，准备更新，再确认执行。Windows 和 Linux 都需要高危操作二次验证。组网时，执行节点必须是已进入维护状态的备机，三成员健康；人工灾难接管中或组网迁移未完成时不能更新。已登记节点即使关闭热备，也要能核实仲裁状态没有待完成迁移。

Linux 网页只提交固定动作号。root 辅助器只停止和启动安装时登记的固定服务，文件校验、备份、替换、进度回执均以网关低权限账号执行，不运行上传包中的脚本。它处于独立 systemd cgroup，停止网关不会把更新进程一起杀掉。升级页会显示阶段进度；网关停机期间查询会短暂中断，恢复后继续读取持久回执。执行日志保存在 systemd journal，可按 `<网关服务名>-update.service` 查询。

停服前的本地探针使用本次动作专属的 120 秒随机凭据，绑定原进程并且只能批准一次；批准前重新检查仲裁、维护状态、迁移状态和更新兼容性。重启后的就绪探针验证动作号、私有凭据、新进程、实际 WebHost 程序摘要及初始化状态。它们仅接受本机回环请求，不接受浏览器登录态或普通 API Token 代替凭据，凭据不返回网页。

失败不会擅自恢复另一版本；如果文件替换阶段失败，服务保持停止，由管理员检查回执和日志后恢复。配置、Data、logs、外部 HA 证书和 Raft 目录不会随程序替换清空。

自定义 `PreservePaths` 会随本次动作传递给低权限文件执行器，仅接受安装目录下的一级目录或文件名，例如 `SiteAssets`。`custom/site` 这样的子路径会明确拒绝，应保留其一级目录 `custom`；程序 DLL、Drivers、前端和兼容描述文件不能加入保留项。执行器在真正停止服务前重新向本机核实集群授权，恢复后还会验证目标动作、进程和实际程序摘要，避免将其他端口上的旧实例误判为升级成功。

自定义保留项只能增加，不会取消 `Data`、日志和站点配置文件的保留。升级数据目录位于程序目录内时，其所属一级目录也自动保留，避免回滚备份递归复制自身；升级目录不能设为程序目录本身、其上级或前端/驱动目录。

## 平台与回滚

新清单为版本 3，明确记录操作系统、架构、RID、net10.0、.NET 主版本、最低 glibc 与支持的 HA 持久格式范围。这些字段纳入发布签名，payload 内对应描述文件也纳入文件摘要。准备和执行前都会重新检查，Linux 辅助器在停机后替换前再检查一次。

- A 使用 `win-x64`；B/C 使用匹配的 `linux-x64`。未指定 RID 时打包脚本默认生成 `win-x64`，不再将其描述为通用跨平台包。
- 旧清单仍可上传校验查看，但缺少可靠兼容信息的旧包和旧回滚点禁止执行，需要重新打包或采用离线备份恢复流程。
- 已执行地址/证书迁移的 HA 持久格式为 3。不能回滚到只支持旧格式的程序。兼容检查不要求 A、B 软件发布版本号相等。
- 回滚只恢复程序，不能倒退共享业务库、证书或 Raft 日志。离线恢复应同时恢复相互匹配的程序与状态备份。
- C 不会随 A/B 的网页更新自动替换；完整包中的独立仲裁组件需按见证成员的维护流程更新。
- Docker 继续使用新镜像替换容器并保留数据卷，不在运行容器内覆盖程序文件。

辅助器程序和固定配置由 root 管理，卸载网关服务会同时移除辅助器的 systemd 单元，保留程序、配置和业务数据以便恢复。
