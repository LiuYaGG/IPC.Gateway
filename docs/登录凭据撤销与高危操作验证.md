# 登录凭据撤销与高危操作验证

## 本轮范围

仅修改登录凭据撤销、登录失败计数与账户节流、高危操作二次验证。没有启用新的通用 API 限流、修改审计正文流程或强制开启其他安全策略。

## 登录凭据何时失效

A、B 使用相同共享业务库和原来的登录签名密钥。两台均需更新本版本，旧版服务不具备共享会话撤销检查能力。

- 注销：将当前会话 ID 写入共享业务库。此会话的 Cookie 或登录 Token 在两台网关上都失效；其他会话保持有效。
- 自己改密、管理员重置密码：更换凭据版本，之前的全部登录会话失效。保存密码使用条件更新，避免已被重置的旧凭据覆盖新密码。
- 禁用后再启用用户：不恢复旧登录会话。
- 删除后新建同名用户：旧用户 ID 不匹配，不能复活旧会话。
- 普通 HTTP 请求在撤销提交后重新验证时直接拒绝。本机现有实时连接会立即收到撤销事件；另一节点上的已有实时连接最多约 5 秒复核一次，在数据库异常时关闭，数据推送本身不会逐条查询身份库。
- 首次升级会拒绝旧四字段格式的 Cookie，需要重新登录一次，不更换现有登录签名密钥。

新增迁移为“202611250001_session_revocation”，增加用户安全版本列及共享会话撤销表，沿用原有数据库迁移锁。过期撤销记录在后续注销时清理，不保存密码或 Token 正文。

## 登录加强

密码验证失败计数使用数据库当前值原子递增，A、B 并发请求不覆盖彼此的失败计数。成功登录和人员编辑只更新各自需要的字段，不把过时整行状态写回。

在已有 IP 和拼图限制之外，每个网关实例增加同一账号每分钟最多 12 次密码验证，包括二次验证和不存在的账号。共享数据库中的锁定状态继续跨节点生效，原有错误次数和锁定期限配置保持有效。

## 高危操作如何使用

在原有确认操作后，网站会居中显示“高危操作二次验证”：

1. 输入当前登录账号的密码。
2. 完成现有滑块拼图。
3. 点击“验证并继续”，只执行刚才那一次请求；取消不会继续执行。

此验证没有新增需要注册或联网的 TOTP 系统。服务端仍检查原来的权限和高可用状态，二次验证不能扩大用户权限。

当前覆盖：

- 执行升级和回滚准备。
- 驱动签名及首次信任签名公钥、修改强制验签策略。
- 人工灾难接管启用与续期。
- 组网迁移准备（包括生成证书）、确认迁移、开启或关闭热备。
- 人员、角色、权限、当前密码等账号管理写操作。

退出人工接管和放弃迁移不增加验证阻挡，便于及时退出危险状态。浏览器本地生成签名私钥不会直接改变网关信任；实际提交签名和信任变更时需要二次验证。

API Token 不用于上述高危交互操作，需使用网页登录账号。

## 实现边界

服务端在动作执行前返回 REAUTH_REQUIRED 和不透明的 contextId。二次验证票据有效 120 秒，一次性使用，绑定当前用户、登录会话、安全版本、网关进程、HTTP 方法、路径、查询字符串和请求正文摘要。换节点、换请求内容、改操作号、超时或重放都不能使用原票据。

票据和验证上下文只保存在本节点内存，不持久化，不进入仲裁日志。切换或重启后需重新验证；超时请取消并重新打开原操作。

前端只在收到明确的“尚未执行、需要二次验证”错误时重试原请求一次。网络断开、服务器异常、一般权限不足不自动重发，以免重复执行未知结果的操作。注销、切换登录或取消原请求会清理验证弹窗和密码。
