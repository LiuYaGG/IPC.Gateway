# PLC 采集实时性与调度策略

本文说明网关如何在健康采集、配置变更和故障恢复同时发生时安排读取，以及怎样判断延迟来自排队、协议请求还是网页展示。相关实现位于 `src/IPC.Gateway.Core/Engine`；网页推送位于 `src/IPC.Gateway.WebHost/GatewayRuntimePushHostedService.cs`。

## 一、目标与适用边界

采集侧优先保证健康点持续刷新，同时让新增点及时获得首值、断线设备及时得到恢复机会、坏点修复后及时重新加入正常采集。上述目标通过有界工作轮次、公平轮转、独立恢复探测和配置版本校验共同实现。

同一设备仍由一个 Actor 串行执行操作。同一串口、总线或其他需要互斥的物理通道也保持串行；创建多个逻辑队列不会让同一条线路上的报文安全地同时执行。已经发出的报文不能靠调整队列优先级直接抢占，必须等驱动完成、超时退出或安全中断。

调度周期、探测周期和浏览器推送周期均是安排工作的频率，不是单点延迟上限。大量设备共用串行线路、设备本身响应缓慢、驱动不响应取消或机器持续过载时，实际等待会更长。

## 二、三类标签任务与设备恢复任务

| 任务 | 进入条件 | 执行方式 | 退出条件 |
| --- | --- | --- | --- |
| 健康标签读取 | 正常点到达采样时间 | 优先使用协议支持的批读；限制每轮点数和连续占用时间，保留轮转位置 | 完成本轮后按采样周期继续；发生明确点位错误或不确定失败则转入独立探测 |
| 新增、修改点的首读 | 新增标签，或地址、类型、长度、偏移等读取定义发生变化 | 尽快进入首读集合；每轮有数量上限，避免一次导入大量点位长期挤占健康读取 | 首次有效成功读取后进入健康集合；读取失败按错误范围转移 |
| 坏点或可疑点探测 | 地址、类型等明确错误，或超时、异常批响应等需要进一步验证的情况 | 从健康批次移出，使用小范围独立请求，按照点位轮转 | 独立读取成功后恢复正常调度；失败后等待下一次探测 |
| 设备恢复探测 | 连接、会话或传输失败，需要确认设备是否恢复 | 使用受限恢复并发，建立连接后选取可用探针；保留轮转信息 | 有效读取或明确的 PLC 点位拒绝响应证明通信恢复；点位错误仍由点位自身处理 |

新增点的优先级不能演变为无限优先；健康点需要持续获得执行机会。设备恢复也不能始终抢在正常读取之前。通道内部正常读取和恢复共用总并发上限，恢复最多占用一个执行位置；通道饱和且有正常读取等待时，连续恢复需要向正常读取让出机会。

## 三、一个工作轮次怎样让出资源

设备读取不再把“完整扫完所有点位”作为一次不可分割的任务。每个轮次只处理有界数量的工作，并在安全边界结束本轮，让其他任务有机会进入。

- 首读集合、健康集合和探测集合分别保留进度，后续轮次从适当位置继续，不因一次失败总是从列表头重新开始。
- 健康批读只包含适合本轮执行的正常点；已隔离或待验证点不应在到期后直接重新混入健康大批次。
- 单读驱动也有每轮读取次数限制。轮次时间预算在请求间检查，不会在一个同步驱动调用尚未结束时释放设备所有权。
- 未执行的标签属于延期，不等于读取失败；不增加其真实读取失败计数，也不将已有正常值直接改成读取错误。
- 写请求按设备先进先出。设备空闲时，队首请求才参与通道调度，每台设备同时最多执行一次采集或写入。单通道最多容纳 256 个等待写入的请求。有读取需求时，连续两次写入后给读取机会。禁用通道会撤销仍在等待准入的写请求。

周期读取使用每台设备的固定时间起点。每个标签按自己的有效采样周期计算下一个计划时刻。调度或通信晚于计划时，完成当前读取后直接进入未来的时刻。新增点仍可立即参与首读，坏点继续使用独立恢复周期。

对提供物理地址信息的驱动，网关会在限制每轮标签数之前，按存储区和地址排序。设备直属标签和不同界面分组下的标签可以一起批读。同批次中，地址、类型、长度和偏移完全一致的标签可以共享一次物理读取，各标签独立计算工程值并更新质量。每个驱动仍按自身的报文容量和可合并的地址范围发起请求。

通道的并发记账按通道 ID 跨配置版本复用。降低并发上限时先等待旧租约自然归还，禁止通过更换信号量让新旧配置各自获得一套并发额度。删除后使用同一 ID 重新加入时，也沿用尚未归还的旧租约记账。

## 四、坏点隔离、批读诊断与恢复

### 1. 按证据区分错误范围

地址不存在、类型不匹配、长度越界等明确点位错误只影响对应点位。连接关闭、会话失效、无有效传输响应等问题按连接故障处理。一次批次结构错误不代表所有点位都配置错误；一次超时也不能单凭错误文字认定某个地址一定无效。

疑似超时点暂时从健康批次移出，使用独立探测，并通过其他可用点确认设备状态。恢复后不能又从同一个超时点开始阻塞全部好点。即使连续恢复成功，也要保留足够的轮转信息，避免仅反复刷新某个“已知好点”。

### 2. 诊断拆分限制为额外四次请求

对于允许拆分的批次失败，一次恢复上下文最多安排四次额外诊断请求，并保留单项验证机会。原始正常请求不计入这四次额外诊断。

诊断预算用完后，尚未确定的点位返回延期结果，由后续轮次继续验证，不伪造成真实 PLC 地址错误。已完成的成功结果继续保留。传输已经失败或请求取消后，停止在同一故障会话中继续发送后续请求。

无法组合读取的边界按客户端实例和请求定义缓存，容量有上限并会过期。连接、读取定义或请求组合变化后，不依赖永久缓存猜测 PLC 的当前能力。

### 3. 动态坏点默认每秒获得一次到期机会

`TagRecoveryProbeIntervalMs` 默认 1000 毫秒。动态坏点和可疑点不再因为长期失败无限增加到数分钟的探测间隔；到期后进入公平探测集合，成功一次即可恢复正常刷新。

“每秒到期”表示每秒可以被安排探测，不保证在同一条繁忙总线上每个坏点都恰好每秒收到一个请求。实际开始时间还受总线互斥、其他任务和驱动请求耗时影响。静态校验不通过的配置需要先修改地址、类型或长度，不能靠反复向设备发送无效请求恢复。

## 五、设备重连与同步驱动取消

设备故障使用独立恢复资源及短周期探测，默认探测间隔为 1000 毫秒，恢复任务超时预算为 1000 毫秒。正常设备不需要等待某个离线设备完成长时间的指数退避。

长期配置错误、驱动不可用或工厂创建失败仍受熔断和重试约束，避免无效重连形成资源风暴。没有可用探针也不应被计算为一次新的实际连接失败，不能因此不断增加连接失败计数或丢失快恢复状态。

设备 Actor 和同步 I/O 执行器都限制待执行数量。尚未开始的任务取消后立即退出队列并完成取消，避免继续占用排队容量。已经执行的同步 I/O 则保持设备及物理通道所有权，直到驱动真实返回；不能仅让上层等待超时，就允许断开、重连或另一条读取与旧 I/O 并发。

因此，第三方同步驱动必须设置有效的底层读写超时。网关无法安全强制终止任意不返回的第三方同步函数；持续不返回仍可能占用其执行线程及所属设备或总线。

## 六、配置版本与旧结果处理

每次运行配置发布都有执行代次，标签还具有读取定义身份。旧请求和旧订阅回调执行前后，都需要确认设备仍存在、父级仍启用、读取定义仍匹配。

- 只修改名称、描述等元数据时，保留连接、健康读取进度和坏点状态。
- 修改地址、类型、元素长度或偏移时，仅相应标签重新首读；旧读取不得把旧地址结果写成新配置的当前值。
- 修改采样周期只调整必要的调度信息，避免为了改周期重建设备连接。
- 写请求在真正进入设备执行时重新检查当前配置和写权限，防止排队期间权限已撤销仍继续写入。
- 订阅实例与其创建时的标签映射绑定，不能把旧订阅回调标成回调到达时的新配置版本。

协议订阅通知保持 FIFO。内存达到阈值时使用临时溢出文件保留通知，Actor 唤醒可以合并，通知内容本身不按“只保留最新值”合并，避免静默丢失规则引擎或历史记录需要的中间状态。临时文件用于运行期缓冲，不是跨崩溃恢复日志；持续消费落后或磁盘故障需要另行处理。

## 七、主要参数

下面是代码和示例配置当前采用的默认值，实际运行时以部署配置为准。运行参数位于 `Gateway:Runtime`；设备本身还可以设置采样周期、通信超时和失败重试延迟。

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `SchedulerIntervalMs` | 50 ms | 检查到期工作和准入机会的周期 |
| `MaxReadItemsPerTurn` | 128 | 一个设备读取轮次的标签预算；仍受驱动批次容量限制 |
| `InitialReadItemsPerTurn` | 16 | 一个轮次中首读工作的数量预算 |
| `SingleReadsPerTurn` | 4 | 单读路径单轮请求数量预算 |
| `ReadTurnBudgetMs` | 50 ms | 请求间检查的轮次让出预算，不是强制中止正在执行的 I/O |
| `TagRecoveryProbeIntervalMs` | 1000 ms | 动态坏点和可疑点的探测到期间隔 |
| `RecoveryProbeIntervalMs` | 1000 ms | 设备恢复探测到期间隔 |
| `RecoveryProbeTimeoutMs` | 1000 ms | 设备恢复任务的超时预算 |
| `MaxConcurrentRecoveryProbes` | 4 | 全局恢复并发额度；仍受通道和物理互斥限制 |
| `DevicePollQueueLimit` | 1024 | 全局待调度设备任务数量上限 |
| `PollTimeoutMs` | 10000 ms | 普通设备工作轮次的任务超时预算 |

Actor 待执行任务默认上限为 2048，通道等待写入默认上限为 256。普通同步 I/O 和恢复同步 I/O 使用各自有界工作池；这些容量限制用于保护资源，不等于 PLC 本身允许的最大连接或并发数。

## 八、指标口径及查询

现有运行状态接口 `GET /api/config/status` 的 `scheduler.acquisitionLatency` 返回四类统计，每类最多保存最近 2048 个有效样本，内存不会随运行时间增长。此接口沿用当前运行状态查看权限。

| 指标 | 起止时间 | 解释限制 |
| --- | --- | --- |
| `initialReadLatencyMs` | 某个读取定义配置生效，到该定义首次成功取得有效值 | 包含采集等待和读取，不等于点击保存到浏览器显示的总时间；没有成功值的点不会伪造零延迟样本 |
| `healthyRefreshGapMs` | 持续健康、读取定义未变的同一点，两次成功读取之间 | 离线、隔离、禁用后重新建立基线；不能把全部停机时长当作健康扫描间隔 |
| `tagProbeQueueDelayMs` | 坏点探测应执行，到实际开始执行 | 反映探测准入等待，不包含整个故障持续时间，也不是坏点从现场修复到恢复显示的完整时间 |
| `deviceProbeQueueDelayMs` | 设备恢复探测应执行，到实际开始执行 | 反映恢复任务排队，不代表设备物理上线时间；网关无法直接知道网线恢复或 PLC 上电的精确瞬间 |

每类统计包含 `count`、`windowCount`、`lastMs`、`averageMs`、`p95Ms`、`p99Ms`、`maxMs`。`count` 为本次统计周期累计有效观察数；其他分布值针对最近 `windowCount` 个样本。P95/P99 使用排序后的最近秩法；样本较少时可能与最大值相同。未采集到样本时，数值为 0 且 `count`、`windowCount` 均为 0，不能据此认为延迟为零。

`sampleCapacity` 是每类样本容量，`sampleTimeUtc` 是快照时间。负数、NaN、无穷等无效样本被拒绝并计入 `rejectedSampleCount`。统计随运行时重置或进程重启清零，不是长期历史数据库，也不是固定“最近一分钟”时间窗口。

建议同时观察 P95/P99、队列长度、可用工作线程和超时计数：首值延迟大而设备探测队列正常，可能是首读压力或设备慢；探测排队持续变长，则应检查共享总线、全局额度或驱动线程是否被占满。聚合指标不能替代对某一个迟迟没有首值的标签检查。

## 九、网页实时推送与采集的区别

浏览器可见且开启实时推送时，服务端按约 100 毫秒收集变化。每个标签只保留当前状态，每帧最多包含 500 个点。积压超过容量时会重新同步。服务端没有浏览器订阅时不保存网页事件历史。

连接建立后，服务端先登记订阅，再发送带开始和结束标记的完整快照。网页收到结束标记后一次替换旧数据，空快照也会清空列表。页面隐藏时关闭推送，恢复可见时重新核对登录会话和当前快照。项目版本变更时还会同步设备树和点位配置。

快照和增量共用后端权限判断。账号或角色变更会关闭受影响的连接，令牌到期后连接结束。网关定期核对权限存储，覆盖在其他进程发生的权限变更。

隔离标志、连续失败次数和下次探测时间通过单独的诊断通知更新到网页。历史、规则和 MQTT 继续消费原有业务变化事件。设备状态约每 500 毫秒采样，系统摘要约每 10 秒推送。

各协议驱动按分组设置采集周期。设备直属标签使用设备的默认周期，分组周期为 0 时也继承设备默认周期。升级前保存过独立采集周期的点位同样遵循这条规则。例如，设备默认周期为 1,000 毫秒、分组周期为 500 毫秒时，直属标签按 1,000 毫秒采集，该分组的所有标签按 500 毫秒采集。

## 十、验收建议

1. 健康设备上保留正常点持续采集，再新增少量正常点，确认原有点不中断且新点尽快取得首值。
2. 分别加入明确错误地址、错误类型和持续超时点，确认正常点持续刷新，失败点独立探测且最近错误来自实际读取。
3. 将坏点修正或让其重新可读，记录首次成功值及随后周期，验证不需要再次编辑保存其他配置。
4. 断开一台设备并保持其他设备在线，再恢复设备，检查恢复探测、正常设备的刷新间隔和共享总线排队。
5. 让第一个标签持续超时，后面保留两个正常点，验证两个正常点都能继续得到读取机会，而不是仅一个探针反复成功。
6. 同时进行配置保存、订阅回调、排队写入和禁用操作，确认旧读定义、旧权限和已禁用设备不会继续成为有效操作。
7. 记录采集侧指标以及浏览器收到时间，分别评估排队、I/O 和展示延迟；不要仅根据某次快速结果承诺全部设备始终“秒级”。

需要测量物理断线恢复时间时，应由测试程序同时记录模拟器或线路实际恢复的时刻，再与网关首次有效值比较；该结果应注明设备数量、协议、总线共享关系、采样周期及超时配置。

## 十一、驱动升级时核对已有配置

- Modbus 的 `HR`、`IR`、`C`、`DI` 等显式区名前缀后填写从零开始的区内地址。例如 `HR10001` 访问保持寄存器偏移 10001。旧版可能将它误算为偏移 0；若原意确实是偏移 0，请改填 `HR0`。传统不带前缀的 `40001` 仍表示第一个保持寄存器。四种 Modbus 传输均适用。`.bit` 后缀仅用于寄存器的 Bool 或 BoolArray。
- 三菱 MC 1E 的 X/Y 地址按机型解释。显式选择 A 或 Q 兼容 1E 时使用十六进制，FX3 和 FX5 兼容 1E 使用八进制。旧配置中的组合选项 `A/FX3` 或缺省机型沿用八进制。例如 `X10` 分别对应十进制 16 和 8，升级前请按 PLC 工程核对。
- 三菱按字读取位软元件时，每个字占 16 个连续位。例如从 `M0` 开始的 UInt16 数组，第二个元素从 `M16` 开始。请核对以位软元件为起点且设置了数组偏移的已有标签。越过报文寻址范围的已配置读写会报错。
- 欧姆龙 FINS 的计数器和定时器使用独立地址。例如 `C0` 和 `T0` 读取各自的当前值，`CU0` 与 `TU0` 访问各自的完成标志。请按 PLC 工程确认既有计数器标签的实际用途。
- MQTT 南向设备的 ClientId 留空时由网关自动生成。旧默认值 `IPC-Gateway-Southbound` 也按自动生成处理。如果 Broker 按固定 ClientId 授权，请给每台设备填写与授权匹配的唯一 ClientId。
- BACnet 的单个数组元素写入会在报文中携带配置的下标。当前驱动通过 WritePropertyMultiple 发送，目标设备需要支持这项服务。
- CANopen 的局部 RPDO 写入按设备的实际 PDO 映射保留相邻输出。无法取得映射或无法读取需要保留的相邻对象时，写入会返回错误。
