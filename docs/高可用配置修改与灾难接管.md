# 高可用配置修改与灾难接管

本次功能需要更新 A、B 网关和 C 见证成员。普通网关版本号可以不同；使用新的三节点组网变更功能时，三个成员都必须具备该功能，旧成员会在准备阶段被明确拒绝。

## 切换记录

“系统 → 高可用 → 切换记录”首次打开默认查询本地昨天此刻至今天此刻，精确到秒。切换其他页面再回来会保留已输入的查询条件。

关闭双机热备后，仍会向已经登记的仲裁成员查询历史，不再返回空列表。仲裁不可达时显示查询失败，不将通信失败当成没有历史。

记录区分首次授主、计划切换申请、实际接管、自动故障转移和同节点恢复。计划提交不等于切换已完成，详情可查看状态与失败原因。原有仲裁审计每类保留最近 4096 条；已经裁剪或随持久目录删除的记录无法重建。

“PLC 写授权”页签已移除。后台的逐次写入保护仍用于防止旧主继续写 PLC。

当前登录会话提交的计划切换确认完成后，网页立即返回登录页，并清理实时连接和页面缓存。提交后即使切换到其他菜单，网页仍会跟踪同一登录会话的操作结果。若切换途中登录会话失效，则保留操作号，重新登录后可核对结果；不会把失联直接当成切换成功。

## 普通配置修改

在“高可用配置”修改名称、稳定业务入口、首选节点、租约策略或网关管理地址，按“保存草稿 → 连接预检 → 确认应用”操作。

修改网关管理地址后，预检会检查目标确实是登记的集群和节点；仅修改网页文字不会使配置生效。

点击“本机组网配置”也可以加载已登记本机的地址并保存为同一份草稿，再返回配置页预检、应用。

集群 ID 和 A/B/C 节点身份保持原值。它们是持久共识身份；新建另一集群或将 A 改成 B 应使用独立的重新部署流程。

## 修改仲裁地址、端口或证书

这些变更需要三个成员共同确认，不能只把一个表单保存到本机文件。

1. 确认 A、B、C 的持久目录和业务库已有备份，且三个节点已更新本次程序。
2. 按现有关闭热备流程保留一台单机业务网关：先停止另一台业务网关，再在保留节点关闭双机热备。
3. 关闭完成后，可以重新启动另一台网关以参与配置准备；它应显示业务暂停，不能自行恢复单机采集。此时两个网关及 C 的管理通信需要可用。
4. 在保留业务的网关打开“高可用配置”，修改 A、B、C 的仲裁客户端地址、成员通信地址和网关管理地址，保存草稿。
5. 点击“准备组网变更”。可选择重新生成成员和网关证书；新私钥由各节点在本机生成，不在节点之间传送。
6. 核对三个成员准备出来的地址与证书指纹，点击“确认组网变更”。三个成员确认同一份计划后，才提交迁移决定并写入待重启配置。
7. 出现“等待重启”表示配置已持久保存，运行中的监听地址尚未改变。按计划手动重启 A、B、C，重新执行成员预检，通过后再启用双机热备。

“部分成员已写入”时恢复通信并重试原计划，不要另建一个计划。待准备、部分写入或待重启期间，界面和后端都会阻止修改其他草稿、提前启用热备或执行灾难接管。

迁移后的仲裁持久身份和网关登记文件会标记 `controlVersion=3`，用于阻止旧程序错误重放新的迁移控制日志。通信协议仍兼容现有成员，日常运行不要求两个网关的发布版本号一致；但已迁移的持久目录不能直接换回不支持迁移的旧 DLL。需要回退时，应先停止相关服务，再恢复同一时点、互相匹配的程序、组网配置、证书和持久状态备份；不要删除 Raft 日志或仅恢复其中一个身份文件。

迁移会保留原共识 WAL 和审计数据，只在具有三成员一致确认的许可下更新持久地址绑定。程序登记地址的修改不会代替操作系统网卡、DNS 或防火墙配置。

### 服务目录权限

新版本 Linux 安装脚本会为成员服务开放其专属配置目录的写权限及 systemd `ReadWritePaths`，以保存经过授权的待生效配置。A/B 使用内置成员，C 使用独立见证服务。更新已有 C 安装时需要使用新脚本更新服务定义，不能只替换 DLL。

Docker 的见证成员配置目录需要使用新 compose 中的可写专属卷，原有持久状态卷继续保留。Windows 安装目录也需要允许实际服务账号写入专属组网配置目录。

Docker 中变更监听端口还需要同步修改宿主机端口映射。操作系统地址、DNS、防火墙和代理转发配置也应由部署人员同步调整。

## 仅剩一台网关时的人工灾难接管

此功能是多数派失效后的显式应急操作，不会把单个成员变成多数派。

**必须由现场人员确认另一台业务网关已经停机，或已与 PLC 和业务网络隔离。连接超时不能证明对端没有工作；在网络分区两边分别接管会产生双主风险。**

1. 直连存活网关的管理地址。例如只剩 A 时访问 `http://A的IP:5184`。如果 HAProxy 和 C 一起掉线，统一代理地址也不可用。
2. 用具有“管理人工灾难接管”权限的账号登录，打开“系统 → 高可用 → 人工灾难接管”。
3. 界面检查另外两个仲裁成员及另一台业务网关均不可达，本机没有正常业务主身份，且没有待完成组网迁移。
4. 点击“人工灾难接管”，填写原因、选择时长、输入本机节点 ID，并手动勾选已停机或隔离的确认项。
5. 确认后，本机通过公共业务生命周期启动采集、规则、历史、MQTT 等服务；仍需要业务数据库、脚本和模型等依赖可用。是否已经启动完成以业务就绪状态为准。

默认接管期限为 60 分钟，可选择 15 分钟至 24 小时；续期也要重新确认隔离条件和原因。到期会停止人工授权，不能仅依赖网页倒计时。

人工授权只对当前进程有效，重启后需要重新人工接管。本机保存请求、成功、续期、退出及自动撤权的记录，最多保留最近 1000 条事件，不伪装成多数派已提交的决定。

系统持续探测其他成员和另一台网关。任一恢复可达、发现配置异常或监测失败，会撤销人工授权，阻止后续物理写入，再由正常仲裁决定能否恢复业务。所有实际写入仍检查本机当前授权，已排队的写请求也不能在撤权后继续下发。

恢复现场通信前，建议先主动退出人工灾难接管，再恢复其他成员并检查正常授主。界面支持随时“退出人工接管”，不要求对端仍然保持离线。
