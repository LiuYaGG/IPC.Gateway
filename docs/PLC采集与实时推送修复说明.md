# PLC 采集与实时推送修复说明

## 西门子 STRING 写入

- 使用标签配置的字符串长度（`ElementCount`）作为有效载荷容量，范围为 1–254 字节。
- 配置为 30 时，写入标准 `STRING[30]`：最大长度头为 30，实际长度头为截取后的内容字节数，后面固定写入 30 字节。
- 内容不足时补 `0x00`，超过容量时截断；空字符串会清空有效载荷，保留最大长度头。
- 两个长度头不计入配置长度，因此 `STRING[30]` 总共占 32 字节。配置容量应与 PLC 实际预留空间一致。
- 沿用原来的 ASCII 编码，不新增编码转换。前端不再移除字符串首尾空格。
- 不再读取 PLC 字符串头来决定写入容量，也不再自动回退到 254。直接调用驱动的字符串写入时必须提供容量。

## 协议及采集

- S7 Bool 数组写入按协商 PDU 分包，分段地址按位推进，保留起始位偏移。
- CIP 批读同时估算请求和响应大小；数组分段使用配置限制及保守响应预算。
- CIP 容量不足和不支持批量服务不再按断线处理。批量容量错误可回退单项读取，数组收到部分传输状态后继续拆分读取。
- 批读中途失败或取消时保留已经完成的结果；采集引擎处理完整结果列表，不再遇到首个连接错误就覆盖后续已经成功的结果。
- 同步驱动在底层 I/O 真正结束前保留执行所有权，避免取消等待后立即与断开、重连等操作重叠。同步调用仍依赖驱动本身的 I/O 超时，无法强制中止任意第三方同步代码。

## 内部事件与网页推送

- 内部事件总线，以及历史记录、规则引擎、MQTT 使用的标签事件消费队列，不再因为达到内存队列阈值删除旧事件。
- 阈值以内使用内存；超过阈值时按 FIFO 顺序转存系统临时目录的文件，保持数值和数组类型。消费完毕或队列清理时删除临时文件。
- 这层临时缓存用于运行期间吸收消费峰值，不是跨重启恢复日志。持续过载会增加磁盘占用和处理延迟，磁盘 I/O 故障不属于无限可靠交付保证。
- 网页推送超过 5000 个待更新标签时，触发采集缓存全量快照补发；仍按每批最多 500 个标签发送。
- HTTP 完整刷新期间暂停 SSE，完成后重新建立连接获取当前快照；完整刷新合并时保留同一标签已经收到的较新值，移除已不存在的标签。

## 其他协议的字符串读写修复（2026-11-10）

### 配置约定

- 标签配置的长度按字节计算，作为用户已经确认正确的容量使用。网关不探测 PLC 实际预留容量，也不检查不同标签是否重叠；保留正数、地址范围、协议类型等必要校验。
- 原始寄存器字符串固定使用配置长度：不足补 `0x00`，超长截断，空字符串清空配置范围，不额外增加结束符。
- 偶数容量直接写入；奇数容量需读取末尾寄存器，保留不属于字符串的另一个字节后合并写入。这是读后写，不是与外部 PLC 程序之间的原子操作。PLC 或其他客户端同时修改该寄存器时，应由现场避免竞争。
- 标准 STRING 的长度头、终止字节和固定结构仍遵循对应协议，不将寄存器规则套用于所有字符串类型。

### 各协议行为

| 协议 | 调整内容 |
| --- | --- |
| Modbus TCP / RTU / ASCII | 按标签容量写入，移除网关写入路径固定82字节的行为；奇数容量保留相邻字节。读取不足配置长度时报错。 |
| 欧姆龙 FINS | 按标签容量写入，不再追加额外结束符；奇数容量保留相邻字节。读取不足配置长度时报错。 |
| 三菱 MC / MC1E / 串口 | 完整驱动原本已实现定长写入及奇数容量相邻字节保留，本次保留此逻辑；补充字符串短响应校验。此前仅查看编码器得出的“补齐字节直接清零”结论不适用于完整调用路径。 |
| EtherNet/IP 周期 I/O | 按配置容量截断、补零，字符串偏移按字节计算；修复 EEIP 输出属性返回副本后未写回的问题，共用的数值和布尔输出也正确写回。UTF-8 截断不拆开一个字符。 |
| CANopen | SDO、RPDO 字符串写入接收标签容量并定长补零；PDO 字符串偏移按字节计算。SDO 读取尊重对象返回长度，并限制在配置容量内；PDO 读取要求完整配置范围。Heartbeat、EMCY 等状态文字不套用字符串存储容量。 |
| ADS | 字符串改用每个标签的容量；`STRING(n)` 读写为 n 个字符字节加一个终止零。旧设备级 `adsStringLength` 不再控制这些标签。字符串批读使用与单读相同路径，单标签长度异常不会阻止后续标签读取。当前实现为 ASCII STRING，不包含 WSTRING 或 UTF-8 STRING 扩展。 |
| S7 / Logix / PCCC | 对不合法或超出响应的字符串长度字段报错，避免静默截短后显示成功。PCCC String 限定使用 ST 文件地址。 |

Logix、PCCC 和 CIP 对象属性继续使用原来的原生字符串结构，不改成无头固定寄存器字符串，也未增加自定义 Logix STRING 容量支持。Logix 默认82字节字符区、PCCC ST 的84字节完整结构保持不变。

网关运行时通过 `IPlcStringWriter` 或带容量的五参数写入方法传递标签长度。Modbus、FINS、ADS、CANopen、周期 I/O 的无容量写入入口拒绝字符串写入，避免绕过定长处理；不影响网页按标签发起的写入。
