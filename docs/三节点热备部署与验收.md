# 三节点热备部署与验收

A、B 在各自的网关服务内运行仲裁成员及客户端，C 运行独立仲裁服务。三台机器各持一票，Raft 日志独立落盘。业务数据库保存业务数据及当前已安装的任期。Windows 服务、Linux systemd 和 Docker 可以混合使用。

## 1. 准备网络、业务库和机器身份

Windows 与 Linux 可以使用不同的网关发布版本和驱动清单。切换根据本机业务就绪、持久退出单机的凭据及多数派租约判断。缺少或未通过本机验签的驱动在设备层面报错。新装、现有服务迁移和卸载请使用[双机热备卸载与重新发布](双机热备卸载与重新发布.md)中的同包入口。

从旧版过渡时，保留每个成员的原身份、证书、业务数据、状态目录及首次启用待办。三个仲裁成员均应升级控制协议，至少有两个新版成员在线才能组成新版多数派。B 曾经持久确认退出单机后下线时，A 可以与 C 完成首次授主。若原记录无法证明 B 已退出单机，则需要让 B 上线完成一次确认。只有 A 一票时不会授主。

| 项目 | 现场准备 |
| --- | --- |
| 三个节点 | 为 A、B、C 各准备唯一、稳定、其他两台可解析的主机名。每个成员默认使用 HTTPS 7281 接受网关调用，使用 HTTPS 7282 与其他成员通信。容器也填写从其他机器可达的地址。 |
| 两个网关 | A、B 使用同一业务数据库、可解密相同配置的密钥、匹配的项目、脚本、模型和已批准的驱动。每台保留自己的数据目录、机器身份和监听地址。 |
| 五张证书 | A、B、C 各使用独立的仲裁证书，A、B 另外各使用一张网关客户端证书。仲裁证书需要匹配主机名的 SAN 以及服务端和客户端用途，网关证书需要客户端用途。记录五张证书各自的 SHA-256 指纹（64 位十六进制）。证书私钥只部署到所属节点。 |
| 稳定访问地址 | 在现场的代理或负载均衡器上配置 A、B。业务就绪探针为各网关的 `/health/ha-active`。返回 HTTP 200 的节点可以接收业务流量。管理和排障可直连 A、B。 |
| 点位历史接续 | 在 A、B 各部署对端历史目录的只读挂载，例如现场现有的 SMB 或 NFS。挂载可以直接由另一台网关提供。热目录与冷目录使用不同路径，在各自的网关配置中登记。本机写入目录使用本机磁盘。 |

## 2. 安装各角色与生成身份

使用对应平台包，按照[双机热备安装、更新与卸载](双机热备卸载与重新发布.md)依次完成以下步骤：

1. 用统一安装入口在 A、B 分别安装并启动网关。各机的进程同时承载本机投票成员。准备各机的业务生产配置、专属可写身份目录和数据目录。
2. 在 B 网关的高可用界面登记本机身份并生成配对码；在 C 的本机向导中登记 C 并生成配对码。
3. 在 A 的高可用界面填写三节点集群信息并配对 B、C。向导在各机生成所需证书，自动交换相应的地址与公钥指纹。
4. 安装并启动独立 C；正常重启 A、B 各自网关服务一次以加载生成的身份。核对 A、B 每台仅有一个业务网关进程、C 一个仲裁进程，所有角色使用独立的持久状态。
5. 已有集群继续使用原身份、任期日志和生产配置。计划更换投票地址时需进行专门的迁移评估。轮换证书时先将新指纹放入相应成员的 `NextCertificateSha256` 或 `NextGatewayCertificateSha256`，逐个维护重启以建立新旧证书重叠的信任窗口。使用向导固定指纹时同步更新业务网关的连接凭据，供所有客户端信任新证书。

## 共享脚本、模型与规则

规则和流程定义随项目 Protobuf 保存在业务数据库。脚本中心的定义、发布历史、数据库连接及写入目标保存到共享资源记录；模型中心同时保存模型目录、历史版本和实际 ONNX 文件。模型二进制按 SHA-256 分块存储，节点只在完整校验后切换本机缓存。模型上传不持有业务主身份锁。

首次更新时，由单机或当前主节点将原本机脚本及模型目录自动迁入共享库，并保留原件。先完成原主节点迁移再启动新备机。共享记录存在后，空本地目录使用共享数据；备用节点不能覆盖共享配置。A、B 必须连接同一业务库，并使用相同的 `Gateway.Security.SecretStorage.MasterKey` 解密脚本连接等凭据。复制生产配置时按机器分别保留身份、监听地址和证书。

脚本后台每秒检查共享版本，模型后台每两秒检查共享版本。点位采集、脚本执行和推理使用已加载内存和本机缓存。备机就绪和接管前重新核对共享资源。保存使用版本检查，同一版本的并发保存只允许一个成功，另一操作需要重新加载。

规则窗口统计、无变化计时和工艺节拍等内存状态在接管后重新预热。脚本待写数据库任务仍保存在来源节点的队列，跨任期的旧任务按现行规则拒绝重放；恢复共享定义不会把旧任务移交备机。节点私钥、仲裁日志、驱动信任和历史分卷继续使用各自的持久目录。

## 3. 从网站启用

1. 登录 A，在 **系统 → 高可用 → 高可用配置** 核对集群标识、显示名、稳定业务地址、首选节点、三方端点与已登记指纹。联调可从每秒续约、租约五秒开始。
2. 保存草稿，点击连接预检，核对本机与其他成员的投票通信及身份清单。
3. 启用并确认。通过操作号检查首次登记进展，等待业务排空、就绪及多数派确认；跨机软件版本和驱动清单允许不同。
4. 在 **集群总览** 核对主机、业务任期和三票的可达状态。按职能授予查看高可用、管理配置、计划切换、维护和查看 PLC 写授权权限。

首次登记会按原事件 ID 将现有单机待处理、未闭环报警和关键待发记录导入共享业务库。启用前已办结的报警保存在原本机 SQLite 文件。点位历史的自动增量复制从首次集群任期起生效，两个节点各自保留启用前的本地分卷。如需在两台查询此前的旧点位历史，需要另行归并旧分卷。普通 MQTT 遥测积压仍沿用来源节点的投递策略。

## 4. 上线验收

| 操作 | 验收条件 |
| --- | --- |
| 计划从 A 切到 B | 选择就绪的 B 并填写原因。原主排空，B 的业务探针返回 200，业务任期递增，旧任期的新写请求被拒。 |
| 停止 A 或只断开 A 到仲裁的链路 | B 和 C 保持通信。B 在旧租约安全到期且本机就绪后接管。分别记录授主任期、业务探针就绪时间、PLC 的首个有效样本。 |
| 只剩一票 | 验证失去多数派后不能得到新的 PLC 写许可。恢复两票后检查原设备命令没有自动补发。 |
| 有报警和积压时切换 | 用稳定事件 ID 对照切换前后的未闭环报警、处理状态及关键 MQTT 待发消息。在代理确认丢失的情况下，订阅端按同一 ID 去重。 |
| 有点位历史时切换 | 检查对端历史挂载和复制进度，在新主查询跨切换时间的曲线。异步复制有延迟，旧主永久丢失时，其尚未复制的尾部需要单独计入数据缺口。 |
| 滚动升级 | 先交接业务，核对三个成员连通，再将目标节点置于维护。逐台升级，恢复就绪并退出维护后再操作下一台。 |

逐次写授权以仲裁日志提交位置为界。在 B 获得新任期前已批准的具体尝试可按原约定完成。日志中的“已授权”只表示批准下发，设备结果须核对驱动确认。自定义驱动须接入分片与重试的热备授权契约，并将验收过的程序集 SHA-256 加入 A、B 的 `Gateway:HighAvailability:VerifiedWriteDriverSha256` 清单。未准入的驱动在集群模式中拒绝写入。

外部 PLC 写请求应保存同一次调用的 `X-IPC-Command-Id` 和 `X-IPC-Expected-Epoch`。当前任期根据单调序号拒绝已过窗口的旧申请，跨任期另外保存最近 16,384 笔已批准的具体写尝试；一个分片占一笔。窗口随多数派状态和快照恢复。客户端重试老命令时保留两项原值，切主后原任期会被拒绝。对于下发结果未知的写操作，先核实设备状态，尤其是脉冲、计数和启动命令。

## 5. 既有仲裁与业务行为的隔离验证记录

| 协议写入范围 | 集群模式中的行为 |
| --- | --- |
| Siemens S7、三菱 MC、欧姆龙 FINS、Rockwell CIP、显式 EtherNet/IP、PCCC、Modbus TCP/UDP/RTU/ASCII、VirtualPLC | 已接入热备写授权。随网关发布的驱动程序集与构建时的摘要核对，单次写入、分片及结果按驱动实现记录。 |
| 三菱 MC1E 与串行系列、DL/T 645、CJ/T 188、CANopen、BACnet/IP、OPC UA/DA 南向客户端、ADS、SNMP、MQTT 南向客户端、DNP3、未经核验的自定义驱动 | 尚未准入热备写入。工业现场需要写这些协议时，先完成该驱动的逐次发送适配和验收。 |
| EtherNet/IP 隐式 I/O | 建连后会持续产生输出，在热备模式下也限制这种连接。 |

- 在一台 Windows 主机启动三个独立仲裁进程、两个独立网关进程。首次组网经过管理 API 的草稿、预检、应用和回执查询。
- 使用 5 秒租约，终止 A 网关进程的一次观测中，B 在 6.07 秒后业务就绪。另一次仅切断 A 到仲裁的连接，A 的管理 HTTP 仍能访问，B 在 6.86 秒后业务就绪并成功写入及回读虚拟 PLC，随后向 A 写入返回 409。这些时间是隔离环境的样本。
- 通过 Modbus TCP 请求验证跨分片授权。一次写 130 个 UInt16 拆成 123 和 7 个寄存器。首帧到达设备后切断旧主到仲裁的连接，设备只收到首帧。
- 第一帧得到确认、第二帧收不到写授权时，诊断结果为 `Partial`，已确认分片数为 1。模拟设备收到写入后丢失确认时，接口返回 HTTP 502、`Unknown`，设备只收到一次写入。另用 FINS/UDP 模拟设备验证了随包欧姆龙驱动的指纹准入、写入和回执。主机在线修改项目后，备机自动预热并上报了相同的新项目摘要。
- A 成功写完 130 个寄存器后，切换到 B，用相同命令 ID 再次提交这笔写入，省略预期任期。B 返回 HTTP 409 和 `HA_DUPLICATE_ATTEMPT`，设备端收到零帧。仲裁跨任期保留最近 16,384 次已授权的具体写尝试，客户端重试还应带上首次确认时的预期任期。
- 验证了仲裁日志压缩和快照、落后成员追赶、三个成员全部重启、旧尝试去重、剩余一票时拒绝新写，以及证书轮换后重新加入。
- 使用独立 SQL Server LocalDB 验证两个进程同时迁移、报警和关键待发消息接续、旧主任期不能确认新主已接管的投递。使用本地文件验证历史活动卷追加、断点续传、损坏修复、压缩卷与分卷命名。
- 已验证 Windows、Linux x64 仲裁发布和 Vue 生产构建。systemd、Docker、现场网段、外部代理以及各型号实体 PLC 需在目标环境执行上表验收。
