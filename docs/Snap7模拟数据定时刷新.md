# Snap7 serverdemo 定时刷新数据

入口：`script/windows/启动Snap7数据刷新.cmd`，双击即可。实际脚本为同目录 `刷新Snap7数据.ps1`。默认连接 `127.0.0.1:102`，Rack=0、Slot=0、Basic 连接，DB1、DB2、DB3 每秒生成一次随机数。按 Ctrl+C 或关闭窗口停止。

## 准备

1. 打开 serverdemo，启动 `127.0.0.1` 的服务，并注册 DB1、DB2、DB3。
2. 默认压测模式要求每个 DB 至少 1768 字节；沿用原来每块 2048 字节即可。
3. 脚本使用原生 `snap7.dll`，位数必须匹配 PowerShell。通常将 Snap7 的 Win64 DLL 放在脚本旁即可；也支持 Win32 DLL 与 32 位 PowerShell。本机仓库中的已下载 DLL 可自动发现。脚本不联网下载依赖。
4. 双击启动入口，观察每轮“已写入：DB1, DB2, DB3”。网关设备的 IP 同样配置为 `127.0.0.1`，即可观察点位变化。

脚本不依赖 .NET SDK、Node.js、Python或网关数据库。移动脚本后，只需将相同位数的 `snap7.dll` 一同放置。若自动选中了不匹配的 DLL，可显式指定路径。

## 默认模式：原 1500 点位布局

每个 DB 对应之前建立的 500 点压测布局，包括 Bool、Byte、Int16/UInt16、Int32/UInt32、Int64/UInt64、Float、Double 和各类数组。数据按西门子大端序编码，浮点数生成有限随机值。三块数据分别生成。

| 每个 DB 的字节偏移 | 数据 |
| --- | --- |
| 128～152 | 200 个 Bool |
| 160～199 | 40 个 Byte |
| 208～287 / 288～367 | 各 40 个 Int16 / UInt16 |
| 368～487 / 488～607 | 各 30 个 Int32 / UInt32 |
| 608～767 / 768～927 | 各 20 个 Int64 / UInt64 |
| 928～1087 / 1088～1247 | 40 个 Float / 20 个 Double |
| 1280～1767 | 各类型数组，沿用之前的数组起始地址与长度 |

前 128 字节、布局中的空隙以及 1768 字节以后的数据不会被修改。因此它适用于原来三个“压力测试_DB”分组，不会刷新布局之外的手工标签；如修改过这些区域的点位类型，需要同步调整布局。此模式不生成字符串，也不会修改其他区域内的字符串。

## 自定义启动

在仓库根目录打开 PowerShell：

```powershell
# 默认：每秒刷新三块原有压测点位
.\script\windows\刷新Snap7数据.ps1

# 改为 500 毫秒，指定 DLL，运行 10 轮后退出
.\script\windows\刷新Snap7数据.ps1 -IntervalMs 500 -Snap7Dll 'D:\snap7\win64\snap7.dll' -Cycles 10

# 只检查布局，不连接也不写入
.\script\windows\刷新Snap7数据.ps1 -CheckOnly

# 其他布局：从偏移 0 开始刷新每个 DB 的 2048 字节
.\script\windows\刷新Snap7数据.ps1 -Mode Raw -StartByte 0 -ByteCount 2048
```

Raw 模式会覆盖指定范围内所有字节，不区分标签类型：同一批随机字节解释为浮点数可能出现 NaN/Infinity，解释为西门子字符串可能使长度头失效。需要有意义的数值时使用默认压测模式或按实际地址修改类型布局，不能把 Raw 模式当作任意布局的类型安全生成器。

脚本逐块检查范围并刷新，单块失败会报告 DB 号并继续其他块；连接中断自动重连。处理变慢时不补发积压轮次，“每秒”是正常通信条件下的目标周期。脚本不会启动/停止 Windows 网关服务，也不会更改配置或数据库。

原生接口参考：[Snap7 官方 API](https://snap7.sourceforge.net/snap7_api_ref.html)。

## 验证记录

已使用 Windows PowerShell 5.1 和独立端口 `17102` 的临时 Snap7 服务通过 44 项检查：三块独立随机数据、标量及数组浮点有效性、原始前缀和空隙不变、Raw 指定范围写入、数据块过小时拒绝写入并继续其他块、服务恢复后自动重连。测试服务已关闭，未向用户 `102` 端口的数据块写入。
