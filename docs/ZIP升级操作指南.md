# 在界面上传 ZIP、执行升级和重启

适用于包含“执行升级并重启”功能的新版 IPC Gateway。网关需要以 Windows 服务方式运行，服务账号需要有停止、启动 IPCGateway 服务及写入程序目录的权限。当前电脑的服务账号是 LocalSystem。

1. 更新前备份 SQL Server 数据库。程序回滚点只保存程序文件，不包含数据库。
2. 打开 http://127.0.0.1:5184/，登录管理员账号，或拥有上传、准备升级和执行升级权限的账号。
3. 展开左侧“系统”，进入“安装升级”。
4. 在“上传升级包”区域点击选择 ZIP，或者将 ZIP 拖到虚线上传区域。
5. 等待“升级包已上传”提示，在“升级包列表”核对版本、上传时间和可信状态。默认文件上限为 1024 MB；页面会显示当前配置的上限。
6. 对应包应显示“摘要通过”；如果正式环境启用了强制签名，还必须通过签名校验。
7. 点击包右侧的“准备升级”，确认提示。系统会创建程序回滚点、解压待更新文件，显示待执行动作。
8. 在页面顶部的待执行动作区域点击“执行升级并重启”，核对提示后点击“确认执行”。采集和推送会短暂暂停。
9. 保持页面打开。后台独立进程会重新校验升级包，停止服务、等待旧进程退出、替换文件并启动服务；页面会自动检查恢复状态。
10. 出现“升级完成，服务已恢复”后，点击“刷新进入新版本”，核对当前版本及设备、标签状态。

如果浏览器刷新或关闭，已经启动的独立更新进程仍会继续。重新进入该页面后可以查看动作状态和执行日志路径。页面等待超时不代表更新一定失败，可点击“重新检查恢复状态”，并查看 Windows 服务和执行日志。

需要回滚时，在回滚点列表点击“准备回滚”，再在顶部点击“执行回滚并重启”。程序回滚不会回滚数据库。

注意：

- 上传时会显示实际传输进度并锁定网站操作；文件传输到 100% 后仍需等待后台校验完成，成功或失败后才解除锁定。
- 升级包只保留最近上传成功的 1 个（含 ZIP 和清单），回滚点只保留最新 1 个。旧包、过期暂存文件会自动清理；正在执行的升级受保护，完成后的状态查询会进行后续清理。
- 上传新包会替换旧的待升级包，需要对新包重新点击“准备升级”。未通过校验的新包不会删除现有可用包。
- 升级完成后，页面隐藏“已有待执行的离线动作”提示；完成结果仍保留用于确认恢复状态。

- ZIP 根目录需要有 `ipc-gateway-package.json` 和 `payload`，并具有有效的文件摘要清单。不能直接压缩源码目录上传。
- 使用项目的打包脚本生成 ZIP。打包后不要修改 ZIP 内容，否则摘要校验会失败。
- 执行权限单独控制：“准备升级”权限不自动包含“执行升级并重启”权限。管理员默认具有全部权限，其他角色可在权限分配页配置。
- 当前 Windows 服务未运行时，网页无法执行上传或升级。先通过 Windows“服务”窗口启动 IPCGateway。
- 首次接入新版时需要先替换旧程序；旧版本没有执行按钮，不能通过旧页面直接获得新版功能。
