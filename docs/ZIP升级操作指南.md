# 在界面上传 ZIP、执行升级和重启

适用于包含“执行升级并重启”功能的新版 IPC Gateway。Windows 使用服务独立更新进程；Linux systemd 需要先使用完整包安装一次更新辅助器，见[Linux 网页升级与平台兼容检查](Linux网页升级与平台兼容检查.md)。Docker 使用新镜像更新容器。

1. 更新前备份 SQL Server 数据库。程序回滚点只保存程序文件，不包含数据库。
2. 直连待更新网关的管理地址，例如本机 `http://127.0.0.1:5184/`，登录管理员账号，或拥有上传、准备升级和执行升级权限的账号。组网后的统一业务入口会选择主机，升级备机时不要使用该入口。
3. 展开左侧“系统”，进入“安装升级”。
4. 在“上传升级包”区域点击选择 ZIP，或者将 ZIP 拖到虚线上传区域。
5. 等待“升级包已上传”提示，在“升级包列表”核对版本、上传时间和可信状态。默认文件上限为 1024 MB；页面会显示当前配置的上限。
6. 对应包应显示“摘要通过”；如果正式环境启用了强制签名，还必须通过签名校验。
7. 点击包右侧的“准备升级”，确认提示。系统会创建程序回滚点、解压待更新文件，显示待执行动作。
8. 在页面顶部的待执行动作区域点击“执行升级并重启”，核对提示后点击“确认执行”，再用当前密码与拼图完成高危操作验证。采集和推送会短暂暂停。
9. 保持页面打开。后台独立进程会重新校验升级包，停止服务、等待旧进程退出、替换文件并启动服务；页面会自动检查恢复状态。
10. 出现“升级完成，服务已恢复”后，点击“刷新进入新版本”，核对当前版本及设备、标签状态。

独立进程会停止网关、替换文件、再启动服务，期间提供网页和进度查询的服务会短暂离线。请保持页面打开等待自动检查。Linux 会按校验、停服、备份、替换、启动、就绪确认等阶段保存进度；服务重新响应、页面读到本次动作的 `Applied` 回执后才判定完成。设备和点位较多时，停服和恢复可能耗时较长。可暂时关闭进度窗口，重新进入“安装升级”查看动作状态和执行日志路径。若回执为 `Failed`，请按页面上的具体原因查看对应日志。

组网升级须三成员健康、目标为维护中的备机。推荐依次更新 C、备机，恢复就绪后计划切换，再更新原主机。人工灾难接管或组网迁移未完成时禁止升级。A/B 网关更新包含各自的内置仲裁，C 的独立仲裁组件仍需单独更新，不能通过 A/B 网页远程替换。

需要回滚时，在回滚点列表点击“准备回滚”，再在顶部点击“执行回滚并重启”。程序回滚不会回滚数据库。

注意：

- 上传时会显示实际传输进度并锁定网站操作；文件传输到 100% 后仍需等待后台校验完成，成功或失败后才解除锁定。
- 升级包只保留最近上传成功的 1 个（含 ZIP 和清单），回滚点只保留最新 1 个。旧包、过期暂存文件会自动清理；正在执行的升级受保护，完成后的状态查询会进行后续清理。
- 上传新包会替换旧的待升级包，需要对新包重新点击“准备升级”。未通过校验的新包不会删除现有可用包。
- 升级完成后，页面隐藏“已有待执行的离线动作”提示；完成结果仍保留用于确认恢复状态。

- ZIP 根目录需要有 `ipc-gateway-package.json` 和 `payload`，并具有有效的文件摘要清单。不能直接压缩源码目录上传。
- 使用项目的打包脚本生成 ZIP。打包后不要修改 ZIP 内容，否则摘要校验会失败。
- 执行权限单独控制：“准备升级”权限不自动包含“执行升级并重启”权限。管理员默认具有全部权限，其他角色可在权限分配页配置。
- 当前 Windows 服务未运行时，网页无法执行上传或升级。先通过 Windows“服务”窗口启动 IPCGateway。
- 已有 Windows 网页升级能力的旧版本，可用打包脚本的 `-LegacyUpgradeManifest` 生成首次升级过渡包；默认新包使用清单版本 3。过渡包仍包含受摘要和发布签名保护的平台描述，详见[兼容说明](Linux网页升级与平台兼容检查.md)。
- 若旧版本本来没有执行按钮，需要先通过完整包维护更新；不能通过旧页面直接获得新版执行功能。Linux 首次需要完整包安装独立更新辅助器。
