# 生产配置基线

## 配置与账号

- 生产环境使用 `Production`，显式配置数据库和认证密钥，首次管理员密码由现场设置。
- 认证、角色和操作权限分开管理；不要把开发环境账号当成所有部署的默认账号。
- 保持数据加密主密钥稳定，迁移时一并处理现场密钥和已加密配置。
- 系统已移除商业授权校验。驱动签名、升级包摘要和发布签名用于校验来源及完整性，与商业授权不同。

## 数据与持久化

配置数据库和本地数据要分别备份。历史文件、MQTT 待发队列、证书、脚本、模型不能仅靠 SQL Server 备份恢复。
程序回滚点只保存程序文件，不回滚数据库。重大结构变更前备份数据库与现场配置。
Docker 持久化 `/app/Data`；Windows/Linux 使用固定数据路径，更新时不能随程序目录一起清空。

## 运行与监控

- 采集有设备隔离、超时、快速恢复探测和背压，阈值按现场规模设置。
- 观察设备在线率、标签质量、采集耗时、队列水位、磁盘余量和规则错误。
- 健康检查通过不等于每个 PLC 都在线，应结合设备和标签状态验收。
- Windows 服务恢复、systemd 重启和应用看门狗是单机恢复机制；目前没有主备仲裁和双机热备功能。
- 浏览器后台恢复时只补最新状态；SSE 队列不是历史数据库，不承诺重放所有中间值。

## 平台与升级

Windows 服务支持网页 ZIP 上传、校验、准备、重启执行和程序回滚。
Linux 支持对应平台 ZIP 解压后通过脚本人工更新，目前没有网页一键自动执行器。
Docker 通过镜像和容器重建升级，不在容器内用 ZIP 覆盖程序。
升级包保留最新 1 个，回滚点只保留最新 1 个，正在执行的升级文件受保护。

不同协议和本机库的平台支持分别核对，不把 Windows 上能连接某协议直接等同于 Linux 上也可用。
