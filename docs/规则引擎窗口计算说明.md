# 窗口计算与窗口统计

“窗口计算”位于规则引擎的“处理”分类，输出统计后的数值。它不再使用运算符和比较值。

## 配置与连线

选择统计方法（平均值、最小值、最大值、求和、计数、标准差），设置时间窗口及最大样本数。最大样本数为 0 时不额外指定数量限制，运行时仍有每个窗口最多 10000 个样本的保护上限；时间和数量限制同时生效。

支持单个标签来源的一条数值处理路径，可以串联数据处理、函数、已发布的值处理脚本和多个窗口计算，再连接一个单值判断节点或直接连接动作。多个动作可以共用结果。多标签合流、AND/OR、顺序及模型输入不在这条数值路径的支持范围内，保存时会提示。

- `标签输入 → 窗口计算 → MQTT 发布`：发送当前窗口统计结果。
- `标签输入 → 窗口计算 → 函数节点 → MQTT 发布`：函数表达式中的 `{value}` 是窗口结果。
- `标签输入 → 数据处理 → 窗口计算 → 基础条件 → MQTT 发布`：先处理输入，再计算窗口，再按统计结果判断报警和恢复。

例如输入先后为 10、30，窗口平均值先输出 10，再输出 20；后接 `{value} * 2` 的函数，则输出 20、40。MQTT 消息的 `value` 使用最终结果，原 PLC 点位值不被改写。

## 执行方式

有有效样本即可输出，不必等待窗口时间收满。窗口按采样时间滑动，过期或超过数量上限的旧样本会移除。异常质量和非有限数值不参与计算，同一采样时间不会被事件和定时检查重复计入。网关会检查最新采样，以覆盖数值没有变化的情况；不会把旧缓存通过修改时间戳伪造成新样本。

直接连接 MQTT 时，计算输出的 `eventType` 为 `value`，按新有效样本输出，不生成报警历史，也不执行恢复发送。同一规则的数值动作按顺序处理，仍受动作策略中的延时、冷却和次数限制约束。需要报警及报警历史时，在窗口后连接判断节点，并在 MQTT 节点启用报警消息。

“窗口统计”保留原来的用法：计算统计值后，与运算符、比较值组合判断是否报警。

## 已有流程

已有“窗口计算”节点会使用新的数值输出语义，原先填写的比较条件不再执行。如果以前用它判断报警，请改用“窗口统计”，或在“窗口计算”后补一个判断节点。已有“窗口统计”流程不受影响。

“周期时间”和“工艺节拍”可以继承已连接的“标签输入”点位，不必在节点自身重复选择点位；中间经过处理节点也可以继承。
