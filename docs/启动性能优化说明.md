# 启动性能优化说明

## 优化范围

本次优化驱动升级信任恢复、值处理脚本预编译和独立初始化任务的并行执行。登录放行条件保持不变：后台运行依赖准备完成后才进入就绪状态。

## 升级信任恢复

- 在准备升级及执行升级的校验、暂存阶段，保存驱动信任继承记录，并将对应信任状态摘要、升级包摘要写入离线动作。
- 新宿主启动后，对已准备完成的动作进行轻量核对，不重新校验和解压整个 ZIP。
- 完成凭据保存在升级数据目录的 `DriverTrust/completed-recovery.json` 中，普通服务重启复用凭据；已清理旧 ZIP 时也可跳过已完成的恢复。
- 首次从旧版本升级、缺少完成凭据或可信公钥/验签策略/继承记录发生变化时，仍使用经过完整校验的原 ZIP 和回滚副本恢复。该路径只提取 `Drivers` 和 `Plugins/Drivers` 下的文件。
- 每次包校验只执行一遍完整文件摘要检查，避免在清单读取和包读取中重复检查同一 ZIP。
- 完成凭据仅决定是否重复执行恢复任务，不授予驱动信任。驱动加载仍检查 DLL 内容、清单、公钥及签名/继承记录。回滚动作不复用另一个升级动作的完成凭据。
- 校验继承记录前先核对清单摘要与实际 DLL 摘要，避免先匹配清单中的旧摘要而漏检 DLL 内容变化。

## 脚本准备

- 值处理脚本服务构造函数不再读取配置或编译脚本。
- 项目加载后，扫描启用的通道、设备、分组、标签清洗，以及启用规则的脚本引用，只预编译实际引用的发布版本。固定引用的旧版本仍会准备；未被引用的历史版本按需编译。
- 相同源码与相同脚本执行上下文共享校验结果和执行委托。并发请求同一源码时只编译一次，不重复进行安全检查、Roslyn 编译和委托生成。
- 使用同一个 Roslyn Script 对象完成检查和委托生成。缓存校验结果对外返回副本，调用方不能修改缓存内容来绕过安全检查。
- 脚本索引完整构建后一次替换，配置重载期间不会短暂丢失已有脚本。已删除的脚本不能通过旧编译缓存继续执行。
- 新增引用的按需编译发生在脚本执行超时计时之前。编译和执行仍保持各自的安全检查，错误脚本返回对应点位/规则的受控错误。

## 并行准备与启动顺序

1. 加载项目配置。
2. 并行执行项目引用脚本准备、OPC UA 配置和证书准备；同时在启动线程校验项目、恢复报警状态。
3. 所有准备任务结束后，启动采集调度、内存状态、历史库及 MQTT。
4. 启动 OPC UA 端点、构建地址空间并启动规则引擎。

脚本预编译并发上限为 2，另有一个 OPC UA 准备任务。OPC UA 准备阶段不绑定端口、不读取运行时点位。必需准备任务结束前不启动采集，避免对外发布未经脚本处理的值。启动失败或取消时等待准备任务退出，再清理运行服务。

## 日志与验证

应用日志中的 `GatewayStartup` 增加以下阶段或明细：

- `恢复升级驱动信任`：`PreparedBeforeRestart`、`RecoveredOnce`、`AlreadyCompleted`。
- `并行准备运行依赖`、`预编译项目引用脚本`、`读取值处理脚本配置`、`准备OPC-UA配置与证书`。
- 脚本明细包含引用数、不同源码数、实际编译数、缓存命中数、缺失/无效脚本数及耗时，不记录脚本源码或密钥。

2026-11-16 隔离验证：使用本机现有 13 个已发布脚本定义，合并为 2 份不同源码，首次准备约 842 毫秒，重复准备不足 1 毫秒；此前逐版本准备实测约 5427 毫秒。持久化恢复凭据在同进程新服务实例中复用约 7～8 毫秒，在全新进程中复用约 35 毫秒。30 项回归检查通过，覆盖历史版本和规则引用、普通调度脚本、错误脚本隔离、并发编译合并、重载期间读取、已删除脚本失效、合法升级/回滚、篡改拒绝，以及 1500 点位采集与 OPC UA 地址空间启动及启动取消。

以上是隔离进程结果，不代表生产环境完整启动耗时。生产效果以升级后的实际分段日志为准；本次验证未修改生产数据库、重启或发布在线服务。
