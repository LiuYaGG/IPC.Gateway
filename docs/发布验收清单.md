# 发布验收清单

1. 从根目录打开解决方案，确认项目都位于 `src`，没有测试、测试插件或模拟器项目引用。
2. 在前端目录安装依赖并完成 `npm run build`；再完成根目录 `dotnet build IPC.Gateway.slnx`。
3. 使用 `script/windows/生成安装升级包.ps1` 生成目标平台的安装或升级包。
4. 核对 ZIP 的版本、目标平台、清单、SHA256，以及 `payload` 中的主程序、`wwwroot` 和 `Drivers`。
5. 确认没有打入现场生产配置、凭据、运行数据和开发环境配置。
6. 在目标环境部署，检查 `/health/live`、`/health/ready`、登录、权限和审计。
7. 验证目标协议连接、标量/数组/字符串读取及必要的受控写入；核对地址和数据类型。
8. 检查 MQTT、OPC UA、规则、脚本、历史和模型等实际启用的能力。
9. 按浏览器验收清单检查界面、分页、语言切换、后台恢复和数据刷新。
10. 升级前备份程序、现场配置和数据库。Windows 核对重启执行及回滚；Linux 核对停服替换及恢复；Docker 核对镜像版本和数据卷。
11. 记录版本、平台、设备数量、点位数、采集周期、验证结果和回退方式。历史仿真压力数据不替代目标现场验收。

仓库仅保留产品源码与运维脚本，不包含自动化测试和模拟器。开发机编译成功不能替代目标环境的协议与本机依赖验收。
